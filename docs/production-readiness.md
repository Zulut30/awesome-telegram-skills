# Готовность Awesome Telegram Skills к production

Следующие работы и критерии завершения собраны в [плане выхода в production](production-plan.md).

Текущий статус после [локальной приемки 0.26.0](internal/local-026-acceptance.md) — **64 из 100** требований. Принятые wheel/tarball прошли 92 этапа, 816 Python-тестов с тремя пропусками и 88 TypeScript-тестов; чистая установка магазина прошла 246 проверок Chrome. Разработка 0.27.0 еще не принята. Реальные клиенты, устройства, платежные кабинеты, независимые участники и пилоты не проверены; production-ready по-прежнему не подтверждено. Числа исходного аудита ниже сохранены как исторический снимок.

Аудит от 5 ноября 2026 года. Исходная база: `9d85548`, версия пакетов 0.24.0; изменения этого аудита еще не являются новым релизом. Проверялись исходники, 42 скилла, каталоги, механизмы проверки и локальная поставка. Рабочие Telegram-аккаунты, платежи и пользовательские устройства в аудит не подключались.

## Исходный вывод аудита 0.24.0

Проект пригоден для разработки и ограниченных пилотов с собственными проверками, но обещание production-ready для всей библиотеки пока не подтверждено. В каталоге 51 группа компонентов, все `experimental`; `stable` нет. В реестре плана выполнено 30 из 100 пунктов. Это учет задач, а не процент надежности продукта. Скиллы и runtime-пакеты имеют разные критерии приемки.

Сильные стороны: отдельное ядро Python без обязательного SDK, адаптеры aiogram и python-telegram-bot, строгая проверка initData, серверная identity и объектные права в примере магазина, обработка неизвестного исхода внешней операции, установленный consumer, CI на нескольких ОС, проверка архивов, лицензий, checksums и происхождения сборки. Копируемые скиллы имеют локальные references и проверяемую структуру.

Актуальная [спецификация Agent Skills](https://agentskills.io/specification) сохраняет используемые поля frontmatter и модель постепенного подключения references. Обновление формата всего набора не требуется; проверка структуры остается отдельной от оценки решений агента.

Границы: `SQLiteOnce` защищает только синхронную транзакцию той же SQLite-базы, не сетевой вызов; `UpdateObserver` — наблюдаемость, не durable inbox. Примеры приложений и наличие платежных моделей не доказывают отказоустойчивую эксплуатацию. В этом аудите не проводилась проверка всей инфраструктуры на проникновение.

У скиллов есть отдельные оценки выбора и полезности в `evaluations/reports/`. Описания не менялись: прежний отчет выбора по-прежнему соответствует их hash и старым запросам, что проверяет тест. Новых запросов про Serverless в той выборке нет. Прогоны полезности относятся к прежним текстам, моделям и режимам и показывают зависимость от модели. Нельзя переносить прежний порог качества на измененные инструкции или любую модель агента.

## Актуальные обновления и выполненная адаптация

- [Bot API](https://core.telegram.org/bots/api-changelog): версия 10.3. Повторный машинный diff 185 методов и 400 типов не обнаружил изменений имен и полей. Это не сравнение всей семантики описаний. Переход на выдуманный Bot API 10.4 не нужен.
- [Mini Apps](https://core.telegram.org/bots/webapps#serverless): обнаружены `WebApp.Serverless` и `Serverless.call`. В [руководстве](telegram-serverless.md) и шести скиллах описаны отдельная JavaScript/V8 среда, callback, платформенная identity, объектные права, сборка перед push, миграции, секреты и реальные эффекты CLI. Автоматического перехода с Python нет.
- В runtime 0.24.0 `TelegramNativeAPI` по-прежнему покрывает прежний каталог из 99 методов. Поддержка `Serverless.call` через него не заявляется; для выбранного Serverless-проекта скилл направляет к официальному мосту. Минимальная версия клиента официально не указана. Добавление typed wrapper, обновление каталогов, типов, примеров и consumer-проверок — отдельная будущая поставка, а не произвольный номер version gate.
- Снимок [PyPI](https://pypi.org/project/pyTelegramBotAPI/): pyTelegramBotAPI 4.37.1 требует Python 3.11+. aiogram остается 3.31.0 и объявляет Python `<3.15`. Необходимо учитывать метаданные установленного SDK, даже когда Python 3.15 уже выпущен. В этой работе обновлен справочник, без установки второго SDK в пользовательские проекты.
- [Node.js](https://nodejs.org/en/about/previous-releases): 20 завершил поддержку; 22 и 24 остаются LTS, 26 перешел в LTS. В [политике](versioning.md) исправлены устаревшие статусы. Production-проекту следует использовать поддерживаемую LTS; Node 26 требует отдельного прогона нашей матрицы, а повышение `engines` — объявленного изменения следующей minor.
- Найдены и исправлены ошибки инструментов: валидатор обходил старые сборки/consumer-окружения, генератор навыка записывал запрещенные самим валидатором CRLF на Windows, а проверка рецептов требовала UTF-8 от дочернего процесса, в котором `-I` отключал переменную `PYTHONUTF8`. Для изолированных запусков теперь явно задан `-X utf8`. Строгая проверка исходников и изоляция сохранены.

## Проверки этого изменения

Локальная среда: Windows, Python 3.13.12, Node.js 24.19.0. Проверки других ОС и Node.js 26 для этих изменений не выполнялись.

- `uv run --with "PyYAML>=6,<7" python scripts/validate_skills.py`: 42 скилла прошли metadata, standalone links и синтаксис Python.
- Reference validator `skills-ref==0.1.1`, команда `agentskills validate`: все 42 скилла прошли проверку.
- `uv run --with "PyYAML>=6,<7" python -m unittest discover -s tests -v`: 204 теста прошли.
- `npm.cmd ci`: установка workspace прошла, npm сообщил 0 известных уязвимостей. Это ограниченный результат npm audit, не аудит безопасности всего продукта или Python-зависимостей.
- `uvx pip-audit -r requirements/sdk.txt`: проверены 27 разрешенных зависимостей, известных уязвимостей не найдено, пропущенных пакетов нет. Результат относится к этому снимку требований и базе advisory на момент запроса, не к логике приложения или всем возможным extras пользователя.
- Календарь установленного wheel дополнительно проверен в отдельном окружении с новой `tzdata==2026.6`: 21 тест прошел. Записанные offline-рецепты остаются на `2026.5`, как требуют их сохраненные fixtures; это ограничение воспроизводимости рецепта, а не запрет новой версии в публичном calendar extra.
- `scripts/build_docs_site.py` и `scripts/verify_docs_site.py`: сайт собран, 491 страница и 20 777 локальных ссылок проверены; ошибок нет. Это проверка сборки и ссылок, не визуальная приемка на устройствах.
- `python -m unittest discover -s site/tests -v`: 7 тестов операций сборки сайта прошли, включая сохранение существующего output при отказе и соответствие navigation manifest.
- Семь измененных скиллов установлены штатным `install_skills.py` в отдельный проект: локальные ссылки остаются внутри собственных каталогов, шесть копий Serverless-руководства совпадают с источником побайтно.
- `scripts/check_registry_names.py`: PyPI и npm вернули 404 для выбранных имен, npm scope также не найден. Это снимок доступности имени, не его резервирование и не подтверждение владения; перед публикацией проверку нужно повторить и настроить publisher владельца.
- `sync_skill_references.py --check`, `add_terms_lines.py --check`, `build_docs_map.py --check`, `check_changelog.py` и `git diff --check` проходят.
