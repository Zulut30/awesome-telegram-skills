# Исследование удобства

Проверяем на людях то, что CI проверить не может: понятно ли новичку и опытному разработчику пройти [первый запуск](quickstart.md) и решить задачу с ИИ-агентом и скиллами. Один раунд — 5–8 участников, после него исправляются найденные проблемы, затем повторный раунд на новой версии. Результат засчитывается, когда во втором раунде по обеим задачам медианное время и число ошибок меньше, а доля завершивших не ниже.

## Участники

Отберите 5–8 разработчиков так, чтобы были представлены все уровни: `new-to-bots` (не делал ботов), `aiogram` (ведет бота на aiogram), `mini-app-frontend` (делает frontend Mini App), `ai-agent` (работает через ИИ-агента). Участники второго раунда — новые люди: знакомство с документацией искажает время.

Перед сессией участник соглашается на запись заметок. В файл раунда попадают только анонимный номер (`P1`…`P8`), уровень и измерения — без имен, ников, e-mail, телефонов, токенов и скриншотов с личными данными.

## Задачи

| ID | Задача | Готово, когда |
| --- | --- | --- |
| `quickstart` | Пройти первый запуск по документации на своем компьютере | `offline.py` печатает результат с ответами бота |
| `agent-task` | С ИИ-агентом и установленными скиллами добавить в готового бота на aiogram клавиатуру из шести кнопок в два столбца | Бот отвечает клавиатурой 2×3, offline-проверка проходит |

Готовый бот для второй задачи выдайте одинаковым для всех (например, проект из `telegram-patterns init --template bot`).

## Ход сессии

1. Модератор читает задачу и больше не подсказывает, пока участник не попросит помощи или не застрянет на 5 минут. Участник думает вслух.
2. Время — от начала чтения задачи до признака «Готово». Ошибка — неверная команда, тупик, возврат на шаг назад или вопрос модератору.
3. Исход: `completed` (сам), `with-help` (с подсказкой), `failed` (не закончил за 60 минут).
4. После задачи участник оценивает легкость по Single Ease Question: «Насколько легко было выполнить задачу?» от 1 (очень трудно) до 7 (очень легко).
5. Каждая проблема записывается с серьезностью (`blocker` — без помощи дальше не пройти, `major` — потеря больше 5 минут, `minor`) и страницей, где она возникла.

## Запись и анализ

```bash
python scripts/usability_study.py new --round 1      # docs/internal/usability/round-1.json
python scripts/usability_study.py check docs/internal/usability/round-1.json
python scripts/usability_study.py compare docs/internal/usability/round-1.json docs/internal/usability/round-2.json
```

`check` требует 5–8 участников, не меньше 5 сессий на задачу, даты и версию библиотеки и отклоняет личные данные; выдает медианное время, долю завершивших, ошибки на сессию, медиану оценки и число блокеров по задачам. Во втором раунде поле `changes_since_previous` перечисляет исправления с ссылками на коммиты. `compare` завершается с ошибкой, если хотя бы по одной задаче стало не лучше.

Исследование показывает удобство для конкретных людей и версии; оно не заменяет автоматические проверки и не обобщается на всех разработчиков.
