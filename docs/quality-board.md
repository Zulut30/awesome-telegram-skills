# Табло качества

Числа ниже собирает `scripts/build_quality_board.py` при каждой сборке сайта: workflow документации запускает его в GitHub Actions после каждого изменения `main` и раз в день, поэтому табло на сайте следует за CI. В репозитории на GitHub эта страница показывает только описание; сами числа — на [сайте документации](https://zulut30.github.io/awesome-telegram-skills/docs/quality-board/).

| Показатель | Откуда | Что значит |
| --- | --- | --- |
| Зеленые проверки | Последние 30 завершенных запусков `Repository checks` на `main` и последний `Full acceptance` (GitHub API) | Доля запусков, где прошли все обязательные задачи |
| Выбор скиллов | `evaluations/reports/skill-selection-latest.json` | Как часто агент выбирает правильный скилл только по имени и описанию. Порог 95% относится к режиму, где агент сначала коротко сопоставляет запрос с описаниями; строка «сразу, только имя» — строгая проверка без порога. Модели названы точными ID |
| Польза скиллов | `evaluations/reports/skill-value-latest.json` | Сколько задач решено по всем критериям с скиллом и без него |
| Покрытие Bot API | Индекс Bot API, `catalog/recipe-gallery.json`, `catalog/capability-map.json` | Методы с рецептом, где запрос собирает SDK, и методы, для которых есть компонент библиотеки |
| Сверка с документацией | Строки «Проверено» в скиллах и [журнал источников](sources.md) | Самая старая и самая новая сверка; старше квартала — повод для [ежеквартальной сверки](sources.md) |
| Проверено вживую | [Живая приемка](live-acceptance.md) и [проверка на устройствах](device-qa-checklist.md) | Случаи, прошедшие в настоящем Telegram; ноль значит, что живой проверки еще не было |
| Последняя приемка | [История приемки](acceptance-history.md) | Версия, дата, этапы и тесты последней принятой поставки |

Если сайт собран без доступа к GitHub API (локально или в форке), строки CI показывают «нет данных», остальное считается из файлов репозитория.
