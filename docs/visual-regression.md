# Сравнение скриншотов

`tools/visual-regression/` собирает кандидаты эталонов шести UI-композиций и
сравнивает PNG без нового сервиса или Python-зависимостей. Сравнение дополняет
[проверку интерфейса](mini-app-ui.md) и [проверку устройств](device-qa-checklist.md).
Пиксели не подтверждают доступность, выполнение действий, качество дизайна или
работу Telegram-клиента.

## Собрать кандидаты

Нужны уже установленные npm-зависимости checkout (`npm.cmd ci` в PowerShell),
Chrome или `CHROME_PATH` и отдельный consumer с установленными UI-артефактами.
Consumer содержит `vendor/`, `example/`, `reference/` и `index.html`, как результат
`verify_ui_kit.py`; эти каталоги не должны быть ссылками. Создайте только родитель
output. Каталог конкретного запуска должен отсутствовать.

```powershell
node tools/visual-regression/capture.mjs --consumer 'C:/owned-ui-consumer' --output output/visual-capture-001
python tools/visual-regression/compare.py candidate --capture output/visual-capture-001/capture.json --output output/visual-baseline-001
```

Capture запускает только loopback preview с предоставленными compiled assets;
внешние запросы страницы блокируются. Это контроль runner, а не OS sandbox.
Данные явно учебные, Telegram не подменяется
«успешным подключением». Снимаются каталог, товар, корзина, профиль, настройки и
запись в состояниях `ready`, `loading`, `empty`, `error`: 320×568, 768×1024 и
1280×800, обе темы, всего 144 сочетания. Снимок охватывает видимую композицию;
shell, tabs, модальные окна и другие приложения этим набором не покрываются.

Runner ждет состояния view и готовых шрифтов, отключает движение при снимке,
убирает hover и требует два последовательных побайтово одинаковых PNG.
Manifest сохраняет размеры, тему, язык, состояние, browser/OS/Playwright,
шрифты, scale, параметры данных и SHA-256 исходных файлов. Случайный timeout
не считается готовностью. Измененный browser, OS, шрифт или другая часть
environment требует отдельного сравнимого набора, а не увеличенного допуска.

`candidate` создает копии и manifest с `review_status: awaiting-human-review`,
возвращает exit 1 и не объявляет проверку пройденной. Команд автоматического
обновления или одобрения эталонов нет. Первый actual не становится baseline
только из-за успешного создания файла.

## Просмотр и доверенная привязка

Человек просматривает все затронутые экраны/состояния, ожидаемое изменение и
ограничения набора. SHA-256 просмотренного **полного manifest** фиксируется
через уже используемый доверенный процесс проекта: например, reviewed commit
и защищенную настройку CI. В manifest связаны хеши изображений, матрица,
environment, маски и допуски. Изменение любой части требует нового просмотра.

```powershell
python tools/visual-regression/compare.py compare --baseline output/visual-baseline-001/manifest.json --capture output/visual-capture-002/capture.json --output output/visual-diff-002 --approved-baseline-sha256 $reviewedManifestSha256
```

`$reviewedManifestSha256` берется из результата этого процесса. Не вычисляйте его
автоматически из нового candidate в той же CI-команде: это уничтожает границу
между созданием и просмотром. Поля JSON `approved`, `reviewer` или `review_status`
не дают разрешения. Без внешнего pin сравнение отказывает. Поддельное поле
approval и изменение уже привязанного manifest проверяются негативными тестами.

Pin подтверждает только равенство предоставленным доверенным байтам. Утилита не
аутентифицирует человека и не может доказать, что владелец действительно смотрел
снимки. Поэтому даже успешный report содержит `human_review_verified: false` и
`product_acceptance: false`. Запись reviewer, scope, времени и обсуждения diff
сохраняет сам процесс проекта; произвольный JSON не является таким доказательством.

## Diff и нестабильные области

Для каждого case сохраняются `expected.png`, `actual.png`, `diff.png` и хеши.
`review.html` открывает локальную галерею кандидатов либо expected/actual/diff;
генерация галереи не означает просмотр или одобрение человеком.
Розовый пиксель означает отличие, синий — явную маску, приглушенный серый —
совпадение. Размер canvas равен максимуму размеров двух снимков; изменение
размеров само по себе проваливает проверку. Exit 0 — пиксельное сравнение прошло,
exit 1 — отличие или еще не просмотренный candidate, exit 2 — отказ ввода/вывода.
Существующий output никогда не перезаписывается.

По умолчанию `masks: []`, `max_diff_pixels: 0`, сравнение точное RGBA. Фильтр
сглаживания не исключает отличия автоматически. PNG ограничены 8-bit RGB/RGBA,
без interlace и цветовых/прозрачностных metadata (`gAMA`, `cHRM`, `iCCP`, `sRGB`,
`tRNS`), не более 16 777 216 пикселей и 32 MiB файла; неподдерживаемый формат
отклоняется явно. Это сравнение предоставленных PNG, а не универсальный декодер.

Если действительно переменный элемент нельзя стабилизировать данными, задайте
его прямоугольник в `masks` и конкретную причину длиной хотя бы 20 символов.
Одновременно перечислите `protected_regions` для действий, ошибок и изменяемых
компонентов. Координаты — целые пиксели ожидаемого PNG. Маска за границами,
пересечение с protected region или суммарная площадь выше 10% отклоняются.
Оставлять значимые элементы вне protected regions, чтобы спрятать дефект, нельзя;
их смысл проверяет человек. Автоматическое определение семантики изображения
утилита не обещает.

Допуск `max_diff_pixels` ограничен 0–100; конкретное ненулевое значение требует
измеренной причины в review проекта. Инструмент его не увеличивает. После
изменения масок, координат, допуска или файлов нужен новый просмотренный pin.
Стабильная учебная матрица поставляется без масок и допусков.

## Исполняемая проверка самого инструмента

```powershell
python -m unittest discover -s tests -p test_visual_regression.py -v
```

Тесты создают собственные PNG и каталоги, сравнивают равные файлы, меняют один
видимый пиксель и участок, проверяют diff, затем восстанавливают снимок. Проверены
изменение высоты, маски и защищенные действия, stale hash, другая среда/матрица,
неверный CRC/размер распаковки, выход за корень, ссылки и сохранность caller files.
Для этого baseline имеет `purpose: machine-fixture`; только явный
`--machine-fixture` разрешает сравнение. Этот режим не принимает product candidate
и никогда не является human review.

Фактическое покрытие локального прогона и кандидаты хранятся в
`output/visual-regression-068/`. Пока человек не просмотрел product baseline и
изменения, пункт 068 остается pending. Browser screenshot не является physical
device evidence.

Источник подхода: [Playwright Visual comparisons](https://playwright.dev/docs/test-snapshots),
сверено 6 ноября 2026. Документация предупреждает о зависимости снимков от среды;
используемый здесь Python comparator реализует свое точное RGBA-сравнение, а не
алгоритм Playwright/pixelmatch. Фактические версии runner и Chrome записываются
при каждом capture.
