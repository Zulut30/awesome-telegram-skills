Локальные package/browser проверки и фактическая эксплуатация имеют разные доказательства. Эта запись фиксирует наблюдение GitHub Actions; она не принимает пункты 94–100.

Это исходный эксплуатационный снимок. Последующие проверки и принятые политики
сопоставлены с доказательствами в [приемке 0.28.0](local-028-acceptance.json);
текущий статус каждого требования указан в [регистре](v1-progress.json).

## Ответы на обращения

В scheduled-прогоне [Support response от 5 ноября, 14:55 UTC](https://github.com/Zulut30/awesome-telegram-skills/actions/runs/42049744820) контроль обещанного ответа за три рабочих дня завершился с ошибкой. Скрипт обработал два обращения; ответ сопровождающего не найден, ожидание составило 13 и 18 рабочих дней:

- [#11: Full acceptance failed, main, 19 октября](https://github.com/Zulut30/awesome-telegram-skills/issues/11).
- [#7: изменился индекс Mini Apps](https://github.com/Zulut30/awesome-telegram-skills/issues/7).

Артефакт `support-response` сохранен этим прогоном. Проверка считает рабочими дни с понедельника по пятницу в UTC; праздники не исключаются. Эти числа относятся к указанному запуску, а не к текущему состоянию обращений после него.

Для подтверждения соблюдения сроков нужны фактический разбор обращений и
доступный исполнитель. Принятая политика пункта 97 задает ориентиры по серьезности
и не обещает SLA. Автоматическое уведомление и исправление кода не заменяют ответа
пользователю; наблюдение просроченной очереди сохраняется. Дополнительные
обязательства команды здесь не назначаются.

## Доступные дальнейшие проверки

### Приватный канал безопасности

5 ноября при проверке пункта 94 `GET /repos/Zulut30/awesome-telegram-skills/private-vulnerability-reporting`
вернул `{"enabled":false}`: ссылка в `SECURITY.md` сама по себе не включала канал.
В рамках подготовки репозитория выполнен `PUT` этого endpoint, затем повторный
`GET` подтвердил `{"enabled":true}`. Сообщения, advisory и публичные issues
не создавались. Коннектор GitHub не поддерживает этот endpoint, поэтому использован
авторизованный `gh api` без вывода токена.

По [официальному описанию GitHub](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository)
это включает приватную форму для исследователя. Проверка доставки уведомления
другому сопровождающему и работоспособность обещанных сроков не выполнены.
В первичном снимке пункт 94 оставался pending до обновления политики и проверки
контакта. Последующая проверка подтвердила доступность механизма приема и приняла
этот отдельный пункт; включение настройки не означает приемку сопровождения.

Свежий полный прогон нового исходного commit должен проверить устранение прежних ошибок поставки. Обновления Mini Apps сверяются с официальным источником и действующими SDK. Результаты этих работ сопоставляются с обращениями отдельно; вопросы сопровождения сохраняются в production readiness до фактического решения.
