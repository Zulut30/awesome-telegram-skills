# План из 100 пунктов: проект для каждого Telegram-разработчика

Цель — чтобы любой разработчик Telegram-ботов и Mini Apps (новичок или опытный, на Linux, macOS или Windows, с любым ИИ-агентом) за несколько минут получил работающий результат и мог доверять каждому скиллу, компоненту и примеру.

План составлен 7 октября 2026 года по результатам аудита репозитория версии 0.24.0. Он **дополняет** [план 1.0](library-roadmap-100.md), а не заменяет его: пункты 1.0 остаются в силе. Пометка «v1-NN» означает, что пункт уточняет или ускоряет соответствующий пункт плана 1.0. Пометка «решение владельца» — выбор, который нельзя делать без владельца проекта (AGENTS.md запрещает менять стек или добавлять обязательную инфраструктуру без потребности).

У каждого пункта есть критерий **Готово** — проверяемое условие. Пункт считается выполненным только после проверки этого условия.

## 1–10. Исправить найденное при аудите

1. **Вернуть шаблон `.env.example` стартера.** Правило `.env.*` в `.gitignore` скрывает `packages/python/src/telegram_patterns/resources/starter/.env.example.txt`, файла нет в git. Добавить исключение в `.gitignore`, восстановить и закоммитить файл. *Готово:* на чистом клоне `python -m telegram_patterns init my-bot` создает проект; 461 из 461 теста пакета проходят.
2. **Исправить испорченную кодировку сообщений.** 14 строк в `aiogram.py:100` и `dialog_forms.py:101–330` содержат UTF-8, прочитанный как CP1251 («РљРЅРѕРїРєР°» вместо «Кнопка»). *Готово:* тексты читаются; тест сравнивает видимые пользователю строки с эталоном и падает на последовательностях вида «Р°», «РЅ», «СЃ».
3. **Закрыть утечку токена в `download_media`.** При ответе не 2xx наружу уходит `aiohttp.ClientResponseError` с URL `.../file/bot<TOKEN>/...` (`media_aiogram.py:243`). *Готово:* тест с локальным сервером, отвечающим 404: токена нет ни в `str()`, ни в `repr()`, ни в логе обработчика ошибок.
4. **Сохранять путь `baseUrl` в `ApiClient`.** Сейчас при `https://x/api/v1` путь `/orders` превращается в `https://x/orders` (`api-client.ts:43`). *Готово:* `/orders` и `orders` дают `https://x/api/v1/orders`; поведение описано в README пакета и закреплено тестом.
5. **Точно классифицировать ответы сервера в `ApiClient`.** 409 → `operation-conflict`, 401/403 → ошибка авторизации, 422 → отказ без повтора, 429 → ограничение частоты с учетом `Retry-After`, 5xx → ошибка сервера. *Готово:* таблица статусов в README и тест на каждый статус для чтения и записи.
6. **Ограничить таймаут и оборачивать ранние ошибки.** Таймаут больше 2³¹−1 мс срабатывает через 1 мс; исключения из `headers()` и сериализации тела уходят наружу как обычный `Error`. *Готово:* оба случая возвращают типизированную ошибку пакета; тесты.
7. **Исправить разбиение длинного текста.** `split_formatted` падает с «Duplicate entity» на корректном вводе и может вернуть часть из одних пробелов (`message_text.py:136, 250`). Предпочитать разрыв по переносу строки и пробелу. *Готово:* property-based тест на 10 000 случайных текстов: каждая часть не длиннее лимита и отправляема, склейка частей равна исходному тексту.
8. **Строгая канонизация payload в `SQLiteOnce`.** `{1: 'a'}` и `{'1': 'a'}`, tuple и list дают один хэш; `timeout=nan` принимается (`sqlite_once.py:24–43`). *Готово:* такие пары дают `OperationConflict` или `ValidationFailure`; нечисловой таймаут отклоняется.
9. **Полностью неизменяемый `VerifiedLaunch`.** Вложенные словари `user` можно менять; JSON с `NaN` принимается; `start_param`, `chat_instance`, `query_id` не возвращаются (`initdata.py:84`). *Готово:* попытка изменить вложенное значение падает; поля запуска доступны; тесты.
10. **Читаемые ошибки CLI.** Ошибка печатается JSON с `\uXXXX`, отсутствующий ресурс помечается как «внутренняя ошибка, результат неизвестен» (`cli.py:88`). *Готово:* по умолчанию понятный текст на языке пользователя, `--json` для машин, отдельная категория для проблем установки.

## 61–70. Python-библиотека

61. **Стиль кода.** ruff (lint и format), длина строки не больше 120 символов; переписать 378 длинных строк (до 400 символов) и однострочные `if …: raise`. *Готово:* `ruff check` и `ruff format --check` проходят в CI без исключений.
62. **`mypy --strict` без ошибок.** Сейчас 29 замечаний в 8 файлах (голые `dict` и `tuple`, функции без аннотаций). *Готово:* 0 ошибок, проверка в CI.
63. **Понятные имена модулей.** aiogram импортируют 20 модулей, суффикс `_aiogram` есть у 8; `calendar.py` и `aiogram.py` совпадают с именами модулей stdlib и SDK. Перенести код, зависящий от SDK, в подпакет и сохранить старые импорты через реэкспорт. *Готово:* тест импортирует каждый модуль ядра без установленного aiogram.
64. **Без импорта приватных функций между модулями.** `slots` использует `_json` и `_owned_transaction` из `sqlite_once`; проверки `_text` повторяются в 6 модулях. Вынести в общий внутренний модуль. *Готово:* `grep` не находит импортов `_имя` из соседних модулей.
65. **Версия пакета в коде.** `telegram_patterns.__version__` и `telegram-patterns --version`. *Готово:* значения совпадают с метаданными установленного пакета.
66. **Переопределяемые тексты компонентов.** Тексты по умолчанию берутся из каталога сообщений (ru и en); приложение может заменить любую строку. *Готово:* в обработчиках нет захардкоженных строк; тесты на замену текстов и английскую локаль.
67. **Быстрые тесты.** 461 тест идет около 6 минут. Разделить быстрые unit-тесты и интеграционные с подпроцессами, разрешить параллельный запуск. *Готово:* unit-набор выполняется меньше чем за 30 секунд.
68. **Покрытие кода.** Не меньше 90% строк в целом и 100% ветвлений для `initdata`, `sqlite_once`, `slots`, `message_text`, `media_aiogram`. *Готово:* отчет покрытия в CI, падение ниже порога валит сборку.
69. **Property-based и fuzz-тесты парсеров.** `initData`, форматированный текст, `callback_data`, payload заказов. *Готово:* Hypothesis-тесты в CI; найденные случаи сохраняются как регрессионные.
70. **Совместимость с диапазоном версий aiogram.** Offline-рецепты требуют ровно aiogram 3.31.0 (`execution.py:66–67`); верхняя граница `tzdata<2027` устареет в 2027 году. *Готово:* матрица CI проверяет три последние minor-версии aiogram; ограничения обоснованы в документации.

## 71–80. TypeScript и Mini Apps

## Когда проект можно назвать великолепным

- Свежий клон за 5 минут превращается в работающего бота на Linux, macOS и Windows.
- Нет известных ошибок высокого и среднего приоритета; CI выполняет все тесты пакетов, браузерные проверки и сверку сгенерированных файлов.
- Есть лицензия, `SECURITY.md`, релизы с тегами и установка из registry или Release.
- Скиллы работают минимум в четырех ИИ-агентах; точность выбора не ниже 95%, польза каждого скилла доказана сравнением.
- Каждый метод и тип Bot API 10.3 имеет рецепт или явную границу; новая версия Bot API отражается в каталоге не позже чем через 7 дней.
- Не меньше 10 реальных проектов и живая приемка в тестовом окружении Telegram при каждом релизе.
