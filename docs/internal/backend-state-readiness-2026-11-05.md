# Пункты 41–50: backend и состояние магазина

Проверка 5 ноября 2026. Исходные требования взяты из `docs/internal/v1-progress.json`; статусы этого файла и формальная приемка здесь не меняются. Это сопоставление исходников и локальных доказательств, а не объявление production-готовности.

Действующий магазин использует Python/aiohttp, файловую SQLite и aiogram; frontend вызывает тот же API и доменные операции, что обработчики доверенных платежных updates. Отдельный `examples/mini-app` с loopback mock сохранен. Перед аудитом хеши исходников магазина совпали с прежним отчетом `output/production-run-2026-11-05/shop-integration/report.json` на 209 Chrome-проверок; затем устранены найденные ниже пробелы. Старый отчет не переименовывается в проверку новых файлов.

## Что пришлось исправить

- Объектные права ранее ограничивались владельцем. Добавлены текущие серверные роли `customer`/`viewer`/`blocked`; создание и сохраненный повтор проверяют роль в записывающей транзакции. Новая сессия не возвращает отозванное право.
- `reconcile()` ранее автоматически отправлял сохраненный запрос после 404. Теперь сверка только читает; повтор требует явного нажатия, прежнего UUID/состава/условий и текущих серверных полномочий. Загрузка страницы не создает даже первый заказ, если исходный POST не дошел.
- HTTP-композиция и Telegram-адаптер находились в `main.ts`. Они выделены в `shop-api.ts` и `telegram-adapter.ts`; тот же домен выполняется в Node без DOM, `window` и Telegram.
- Не было законченного пути параметров запуска. Добавлены ограниченные подсказки `catalog`/`orders`, модели menu/main/inline/reply и проверка пяти синтетических профилей; параметры не назначают пользователя или роль.

## Точный предел доказательств

Новый отчет: `output/production-run-2026-11-05/backend-state/final/report.json`, команды и исходные хеши рядом. Локально выполнены 24 Python-теста без skips, четыре headless Node-сценария без skips, строгая TypeScript-сборка, Mypy восьми source-файлов и 246 проверок Chrome 156.0.8078.80. Browser проверяет шесть размеров/тем, cross-site iframe, actual wired UI, триггеры lifecycle, read-only recovery, текущую серверную роль и пять профилей запуска. Два настоящих аварийных завершения backend имеют коды 75/76; платежные/native/launch данные при этом синтетические, внешние запросы запрещены.

Это существующий editable Python environment и frontend из source с workspace vendor build. Они не заменяют fresh wheel/tarball acceptance. `scripts/verify_shop_example.py` дополнен обязательными role/migration/launch именами, минимумом 24 выполненных Python-тестов и отдельным этапом четырех headless Node-сценариев после установки tarball. Он также требует признаки read-only recovery и explicit original retry из Chrome-отчета. Команду надо выполнить на финальных артефактах новой версии; этот документ не утверждает ее результат заранее.

Ни один из пунктов не считается автоматически принятым этой таблицей. Нужны отдельные evidence-bound acceptance commits по исходному плану. Реальные устройства, тестовый бот, платежные кабинеты, участники usability и пилотов отсутствуют; это ограничение сохранено, а не подменено эмуляцией.

Первичный контракт запусков сверялся только в соответствующей части 5 ноября 2026: [Mini Apps launch methods](https://core.telegram.org/bots/webapps#implementing-mini-apps), [WebAppInitData](https://core.telegram.org/bots/webapps#webappinitdata), [bot deep links](https://core.telegram.org/bots/features#deep-linking). Даты всего API/платежного каталога не обновлялись.
