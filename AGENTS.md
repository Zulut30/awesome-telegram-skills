# Работа над Awesome Telegram Skills

Цель проекта — поддерживаемый набор практических навыков для разработки Telegram-ботов и Mini Apps. Канонические навыки находятся в `.agents/skills/`; README содержит их каталог.

Основной стек — Python для ботов и backend, TypeScript для Mini Apps. Для нового Python-бота без других предпочтений отправная библиотека — aiogram; существующие библиотеки сохраняются.

Если задача — подключить библиотеку к другому проекту, начните с `docs/for-agents.md`: отличайте исходный checkout, установленный пакет и один перенесенный скилл. Выберите компонент в `components.json`, подтвердите фактическую версию и точный import по package README / `catalog/api-reference-index.json`. Установка скилла не устанавливает runtime-пакеты; `ref.*` из справочника не является cookbook ID для `run-recipe`. Не загружайте всю документацию ради одного компонента.

- Сохраняйте самостоятельность навыков: после копирования одного каталога все локальные references должны работать. Другие навыки могут быть полезны, но не должны становиться обязательной зависимостью.
- Общие страницы из `docs/`, скопированные в скиллы, правьте только в `docs/`, затем выполните `python scripts/sync_skill_references.py`; список копий — `catalog/skill-references.json`.
- Пишите инструкции на русском, идентификаторы навыков и API — на английском. Название каталога должно совпадать с `name` в YAML frontmatter.
- Делайте descriptions различимыми по намерению пользователя. Не загружайте весь набор ради узкого исправления.
- При изменении зависимого от версии поведения сверяйте официальную документацию и установленную версию библиотеки. Добавляйте использованные источники в навык; дата в docs/sources.md относится только к фактически проверенному содержимому.
- Не подменяйте Bot API автоматизацией пользовательского аккаунта через MTProto. Такая работа требует отдельной явно поставленной задачи.
- Не добавляйте обязательные сервисы, инфраструктуру, сторонние приложения или смену стека без потребности конкретного сценария.
- Готовые компоненты находятся в `packages/python` и `packages/typescript`, каталог — `components.json`. При явной задаче переиспользования подключайте подходящий публичный API, сохраняя стек проекта. Пакеты пока поставляются локально; не предполагайте публикацию в PyPI/npm.
- Изменения общей библиотеки проверяйте ее тестами, сборкой и установкой wheel/tarball в отдельный consumer; синхронизируйте exports, каталог и changelog.
- Полная проверка поставки библиотеки: после `npm ci` (в PowerShell — `npm.cmd ci`) выполните `python scripts/verify_pattern_packages.py` на Windows, Linux или macOS. Нужен Chrome или CHROME_PATH; `--skip-browser` явно оставляет UI непроверенным. Логи и артефакты сохраняются в output/pattern-library-<version>.
- При изменении исполняемых помощников проверяйте их реальные операции в временных каталогах. При изменении инструкций используйте релевантные сценарии из docs/evaluation.md; статическая проверка не доказывает качество решений агента.
- Команды проверки: `uv run --with "PyYAML>=6,<7" python scripts/validate_skills.py` и `python -m unittest discover -s tests -v`.
