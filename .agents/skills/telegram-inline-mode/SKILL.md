# Inline mode

Различайте inline query и callback query. Определите продуктовый сценарий: найти и отправить результат в чат либо перейти в личный диалог. Проверьте настройку inline mode у бота и типы результатов, доступные в установленном SDK.

## Обработка поиска

Нормализуйте запрос, ограничьте нагрузку на поисковый backend и задайте таймаут. Для пустого запроса выберите полезное стартовое состояние, если это соответствует продукту. Не раскрывайте закрытые данные только потому, что пользователь знает идентификатор объекта.

Пагинация должна иметь устойчивый cursor, связанный с текущим запросом и его контекстом. Поддельный или просроченный offset не должен открывать чужой результат или приводить к необработанному исключению.

Идентификатор результата должен быть устойчивым и соответствовать отправляемому объекту. Содержимое сообщения формируйте отдельно от заголовка и превью; безопасно форматируйте пользовательские данные. Проверьте актуальные ограничения количества и размера результатов в API.

## Кеш и приватность

Если выдача зависит от пользователя или его прав, настройте персональный кеш и подходящий срок. Не позволяйте общему кешу смешивать персональные результаты. Изменение прав доступа должно учитываться политикой кеширования.

При необходимости учета выбранных результатов проверьте настройку feedback. Отсутствие такого события не доказывает, что сообщение не было отправлено.

## Проверка

Проверьте пустой запрос, обычный поиск, следующую страницу, неверный cursor и отправку результата в реальный чат на тестовом боте. Для персональных данных проведи сценарий с двумя пользователями. Укажите, какие настройки BotFather нужны и какие проверены.

С библиотекой awesome-telegram-patterns, если она уже есть в проекте: [inline-поиск с пагинацией](references/inline-search.md).
