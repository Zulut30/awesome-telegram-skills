# Особенности capabilities

Таблица указывает решения, а не полный справочник методов. Для реализации читайте раздел конкретного API и документацию версии SDK. Callback может означать согласие, завершение диалога или готовый результат — это разные подтверждения.

| Задача | Важное различие |
| --- | --- |
| Геолокация | LocationManager требует init; доступность и permission различаются; getLocation может вернуть null. Open settings привязан к действию пользователя |
| Биометрия | Проверяйте инициализацию, доступность и разрешения BiometricManager; локальная разблокировка не заменяет серверную сессию и права |
| QR | Обработайте закрытие popup и полученный текст; пользовательский текст недоверенный, произвольный URL не открывается как побочный эффект чтения |
| CloudStorage/DeviceStorage | Храните только подходящие данные, учитывайте ошибки/лимиты и scope конкретного хранилища. DeviceStorage не является общей серверной БД и не обещает перенос на другое устройство |
| SecureStorage | Используйте по контракту для подходящих пользовательских credentials/состояния; проверьте unsupported, clear и restoration permission. Не понижайте защиту молча до localStorage |
| Sharing | shareMessage использует подготовленное сообщение по требуемому протоколу; UI закрытия, принятие запроса и подтвержденная отправка не равнозначны |
| Скачивание | downloadFile callback означает принятие пользователем запроса; он не подтверждает запись файла на диск или дальнейшее открытие |
| Haptics/fullscreen/orientation | Проверяйте поддержку, реальное состояние и пользовательский смысл; не делайте их условием доступности основного действия |

## Жизненный цикл

Init менеджера выполняется до методов, которым это необходимо. Если оборачиваете callback в Promise, предусмотрите завершение по отмене/timeout, чтобы UI не оставался pending навсегда. Timeout не означает отказ системы; поздний результат игнорируется или обрабатывается по актуальному request id. Отклонение повторного запроса во время pending не должно выполнять cleanup активной операции; проверьте повтор с тем же экземпляром adapter, если он переиспользуется. Снимите listeners и завершайте отслеживание сенсоров при завершении владельца.

Для storage отделяйте draft, session credential и серверный объект. Ключ/значение не должны смешивать разных вошедших пользователей; сброс и срок хранения соответствуют типу данных. Секреты backend остаются на сервере. При logout согласуйте очистку локального credential с отзывом серверной сессии.

Результат биометрии или position не используется как доверенная role/price. Серверная операция получает подтвержденную личность и самостоятельно проверяет разрешения. Если требуется дополнительное подтверждение личности, реализуйте явный серверный протокол, а не boolean в body.
