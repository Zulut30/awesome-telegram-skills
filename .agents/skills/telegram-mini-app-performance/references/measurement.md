# Измерение скорости

Согласуйте бюджет с продуктом и его устройствами. Универсального лимита bundle для всех Mini Apps нет. Сохраните build hash/версию, route, сервер, исходные данные, состояние кеша, viewport и CPU/сеть, чтобы повтор был сопоставим.

| Вопрос | Полезное наблюдение |
| --- | --- |
| Когда появился полезный первый экран? | Время до доступного каталога/формы, navigation/resource timing, LCP при доступном observer |
| Почему интерфейс тормозит? | Performance trace, main-thread tasks, события ввода/render и поддерживаемые Event Timing/Web Vitals |
| Почему скачет компоновка? | Layout shifts, незарезервированные изображения/шрифты/вставки и CLS при доступной метрике |
| Почему медленно подтверждение? | Согласованные browser/server spans: сеть, сервер, БД, внешняя интеграция |
| Что входит в загрузку? | Размер отдельных chunks, gzip/brotli при фактическом сжатии, waterfall, кеш и критические зависимости |

## Ограничения метрик

Время `locator.click()` вместе с ожиданием содержит стоимость автоматизации и не является INP. `performance.now()` после появления selector — время этого наблюдения, не LCP. TBT может помогать лабораторной диагностике, но не заменяет INP. При отсутствии поддержки API метрика недоступна, а не равна нулю.

Учитывайте жизненный цикл и iframe/WebView; проверяйте доступность observers и корректность используемой библиотеки на выбранном клиенте. Отдельные искусственные клики не доказывают соответствие полевому percentile. Сверяйте текущие определения и пороги в [Web Vitals](https://web.dev/articles/vitals), если используешь их как критерий.

## Повторяемое сравнение

Измерьте холодную и повторную загрузку по потребности. Выполните несколько запусков; сохраните сырые значения, median/разброс и выбранный критерий. При изменении CPU/сети или стороннего ресурса новый профиль не сравнивается с прежним как единственная переменная. Очистка browser cache не означает пустой CDN/backend cache.

На desktop можно явно задать CPU throttling и сеть; подпишите это как симуляцию. В итоговом отчете отдельно покажите реальный Telegram на слабом устройстве, если он проверен. Демо-данные и localhost не измеряют production latency.

После оптимизации проверьте доступность клавиатурой/касанием, сохранение формы и актуальность ответов. Для виртуализации — длинный список, возврат к выбранной строке и focus на границе видимой области. Изменение cache ключей требует изоляции пользователя и сброса при смене сессии.
