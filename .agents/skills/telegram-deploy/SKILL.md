# Запуск и эксплуатация

Проверьте выбранный хостинг, модель процесса, конфигурацию, storage и способ доставки updates. Не меняйте провайдера или инфраструктуру автоматически. Подготовьте изменения и процедуру проверки, затем выполните авторизованный запуск в указанной среде.

## Polling или webhook

| Условия | Подход |
| --- | --- |
| Постоянный процесс, локальная разработка, простой хостинг | Polling с одним потребителем для конкретного бота |
| HTTPS endpoint, serverless request lifecycle или потребность в HTTP-доставке | Webhook с совместимым adapter |

Перед переключением проверьте текущую конфигурацию бота. Не очищайте pending updates как стандартный шаг запуска. Укажите последствия, если задача действительно требует их сброса.

Для webhook настройте TLS и проверку `X-Telegram-Bot-Api-Secret-Token`. Возвращайте успешный ответ после завершенной обработки либо надежного сохранения update для последующей работы. Подтверждение до записи в durable storage может потерять событие при остановке процесса. Повторы должны быть безопасны для прикладных эффектов.

Для polling проверьте момент продвижения `getUpdates.offset`: следующий запрос с offset выше update_id подтверждает событие независимо от успеха бизнес-операции. Если потеря события недопустима, согласуйте завершение или надежное сохранение с этим моментом и восстановлением после сбоя. Фоновая задача и последовательный режим сами по себе не гарантируют durable прием, особенно если SDK перехватывает исключение обработчика. Не добавляйте очередь обычному боту без такого требования.

## Окружение и релиз

Разделите test и production token, базы и платежные среды. Передавайте секреты через настройки хостинга; проверьте redaction сетевых URL в логах. Для Mini App проверьте публичный HTTPS URL, прямые frontend routes и соответствующие настройки бота.

Применяйте миграции по правилам проекта. При нескольких экземплярах проверьте состояние диалогов, deduplication и конкурентные изменения. Graceful shutdown должен завершать или надежно передавать уже принятые задачи.

Определите health и readiness согласно реально нужным зависимостям. Логи должны позволять связать update с результатом без персонального payload. Добавьте минимальные показатели: ошибки обработки, задержка, backlog и повторные доставки. Масштаб мониторинга выбирайте по проекту.

## Подтверждение запуска

Проверьте процесс, доступность endpoint, `getWebhookInfo` для webhook и один авторизованный пользовательский сценарий. Для Mini App откройте опубликованный URL внутри Telegram. Зафиксируйте примененную версию и восстановление предыдущей рабочей конфигурации. Зеленый health endpoint не подтверждает весь путь пользователя.
