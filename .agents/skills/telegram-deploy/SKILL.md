# Запуск и эксплуатация

Проверь выбранный хостинг, модель процесса, конфигурацию, storage и способ доставки updates. Не меняй провайдера или инфраструктуру автоматически. Подготовь изменения и процедуру проверки, затем выполни авторизованный запуск в указанной среде.

## Polling или webhook

| Условия | Подход |
| --- | --- |
| Постоянный процесс, локальная разработка, простой хостинг | Polling с одним потребителем для конкретного бота |
| HTTPS endpoint, serverless request lifecycle или потребность в HTTP-доставке | Webhook с совместимым adapter |

Перед переключением проверь текущую конфигурацию бота. Не очищай pending updates как стандартный шаг запуска. Укажи последствия, если задача действительно требует их сброса.

Для webhook настрой TLS и проверку `X-Telegram-Bot-Api-Secret-Token`. Возвращай успешный ответ после завершенной обработки либо надежного сохранения update для последующей работы. Подтверждение до записи в durable storage может потерять событие при остановке процесса. Повторы должны быть безопасны для прикладных эффектов.

Для polling проверь момент продвижения `getUpdates.offset`: следующий запрос с offset выше update_id подтверждает событие независимо от успеха бизнес-операции. Если потеря события недопустима, согласуй завершение или надежное сохранение с этим моментом и восстановлением после сбоя. Фоновая задача и последовательный режим сами по себе не гарантируют durable прием, особенно если SDK перехватывает исключение обработчика. Не добавляй очередь обычному боту без такого требования.

## Окружение и релиз

Раздели test и production token, базы и платежные среды. Передавай секреты через настройки хостинга; проверь redaction сетевых URL в логах. Для Mini App проверь публичный HTTPS URL, прямые frontend routes и соответствующие настройки бота.

Применяй миграции по правилам проекта. При нескольких экземплярах проверь состояние диалогов, deduplication и конкурентные изменения. Graceful shutdown должен завершать или надежно передавать уже принятые задачи.

Определи health и readiness согласно реально нужным зависимостям. Логи должны позволять связать update с результатом без персонального payload. Добавь минимальные показатели: ошибки обработки, задержка, backlog и повторные доставки. Масштаб мониторинга выбирай по проекту.

## Подтверждение запуска

Проверь процесс, доступность endpoint, `getWebhookInfo` для webhook и один авторизованный пользовательский сценарий. Для Mini App открой опубликованный URL внутри Telegram. Зафиксируй примененную версию и восстановление предыдущей рабочей конфигурации. Зеленый health endpoint не подтверждает весь путь пользователя.
