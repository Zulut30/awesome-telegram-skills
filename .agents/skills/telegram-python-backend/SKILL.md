# Python backend

Изучите текущий web-framework, ORM/driver, schema и способ подтверждения личности. Сохраняйте выбранный стек; FastAPI и SQLAlchemy — возможные варианты, а не обязательная миграция. Backend и бот используют одни прикладные правила и источник данных.

## Контракт и права

Опишите вход, результат, ошибки и переход состояния одной операции. Личность приходит из проверенной серверной сессии/adapter, а не user_id, цены или роли в body. Проверяйте доступ к объекту и разрешенный переход при каждом действии. CORS и наличие Telegram bridge не являются авторизацией.

Используйте runtime validation для внешнего JSON, bounded pagination и ограничения входных данных по смыслу продукта. Отделите transport модели от ORM; не выдавайте внутренние колонки и исключения. При существующей OpenAPI схеме сохраняйте ее совместимость с TypeScript-клиентом; breaking change делайте явным.

## Хранение и операции

При изменении записей, конкурентных действий или миграций прочитайте [references/persistence.md](references/persistence.md). Задайте границу транзакции, ограничения БД и политику повторного запроса. Не подменяйте durable correctness локальным asyncio.Lock или кешем процесса.

Синхронный DB/HTTP вызов не становится неблокирующим внутри async def. Используйте подходящий driver/framework execution model. Session/transaction принадлежит запросу либо отдельной задаче, не разделяется между конкурентными задачами. У внешних вызовов есть timeout и определенное поведение при неизвестном результате.

## Миграции и проверка

Используйте миграции проекта, проверьте сгенерированный SQL и совместимость существующих строк. Проверьте чистую БД и переход с предыдущей схемы во временной среде. Не запускайте destructive migration в рабочей БД как проверку разработки.

Проверьте прикладной результат через API: собственный/чужой объект, недопустимое состояние, конкурентное создание, повтор, rollback и перезапуск. Используйте реальную целевую БД там, где mock или другая СУБД скрывает риск; явно укажите ограничения локального probe. Сохраните команды запуска, schema/API изменения и фактические результаты.
