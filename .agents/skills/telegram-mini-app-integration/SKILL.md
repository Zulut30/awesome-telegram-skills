# Интеграция бота и Mini App

Нарисуй путь одного пользовательского действия от точки запуска до сохраненного результата. Уточни фактически выбранный способ открытия приложения: от него зависят доступные данные и канал ответа. Не предполагай, что все способы запуска дают одинаковый контекст.

## Запуск

Проверь HTTPS URL, frontend route, настройки бота и требуемые ограничения типа чата. URL должен открывать нужный экран с прямой загрузки, а не только после навигации из корня SPA.

Различай bot deep link (`start`) и Mini App deep link (`startapp`). Используй payload как указатель на сценарий; права доступа устанавливаются отдельно на сервере. Не помещай чувствительные данные в ссылку, которая может попасть в историю или логи.

## Канал обмена

| Сценарий | Канал |
| --- | --- |
| Запуск через reply keyboard `web_app` и короткий результат формы | `sendData` → `web_app_data`; данные формы валидировать на сервере |
| Поддерживаемый запуск с доступным `query_id` и отправка сообщения от имени пользователя | Серверный `answerWebAppQuery` после проверки входных данных |
| Работа с каталогом, заказами и длительной сессией | HTTPS API backend с подтвержденной серверной сессией |

`sendData` не является общим каналом всех Mini Apps. Проверяй его доступность по точке запуска. Не используй `query_id` как единственное доказательство личности.

## Целостность операции

Определи контракт запроса, результат и способ повторной попытки. Бот и Mini App должны читать один бизнес-объект, а не вести несогласованные копии состояния. Заказ получает идентификатор на сервере; повторный запрос с тем же ключом возвращает уже созданный результат.

Уведомление через бот отправляй в доступный чат с учетом пользовательского согласия и правил Telegram. Не считай открытие Mini App доказательством, что бот уже может отправлять личные сообщения.

## Проверка

На тестовой конфигурации проверь прямую ссылку, запуск из выбранной кнопки, холодную загрузку frontend route и завершение действия с отображением результата в боте. Проверь истекшую сессию и повторную отправку запроса. Зафиксируй отдельно изменения кода и фактически примененные настройки бота.
