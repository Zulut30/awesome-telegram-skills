# Данные профиля Telegram

Определи, чей профиль нужен и какая авторизованная сущность получает данные: обычный бот, подключенный business bot или пользовательский клиент. Сначала прочитай [references/profile-access.md](references/profile-access.md). Не устанавливай пользовательскую сессию только ради поля, которое уже доступно боту.

С библиотекой awesome-telegram-patterns, если она уже есть в проекте: [профили и оформление своего бота](references/profiles.md).

Используй устойчивый numeric ID; username может отсутствовать или измениться. Для MTProto правильно разрешай entity/access hash поддерживаемой библиотекой. Разделяй личность пользователя, профиль чата и данные bot account.

Поле в схеме может быть optional или недоступным из-за privacy, контекста и возможностей текущего API. Сохраняй различие между неизвестным значением и подтвержденным отрицательным результатом. Записывай источник и время, если данные используются для решения о доступе.

Фото, bio, Premium, emoji status, дату рождения и personal channel выбирай по конкретной задаче. Флаг verified/premium и отображаемое имя не заменяют серверную роль или проверку владельца заказа. Если функция «проверить аккаунт» означает риск-оценку, покажи полученные факты и ограничения, не выводи надежность человека из аватара или подписки.

Для изменения профиля установи точную цель и новые значения. Собственный бот, подключенный Business-аккаунт и MTProto user session используют разные методы и права; выбери маршрут из reference. Изменяй только запрошенные поля, учитывай language_code для локализованного описания бота и не превращай пропуск поля в его очистку. После операции повторно получи доступные данные и обнови кеш; сетевой timeout не доказывает неуспех.

Телефон и скрытые данные не извлекаются из одного username. При обработке явно переданного contact проверь его привязку к инициатору, если это нужно сценарию. Не публикуй полное содержимое профиля или контактов в диагностических логах.

Проверь профиль без username/фото, отсутствующие optional-поля, недоступный peer, отсутствие нужного права изменения и обновление кеша после смены имени. Для живой проверки работай только с указанными пользователем целями; создание навыка не означает вход в конкретный аккаунт.
