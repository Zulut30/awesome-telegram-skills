# Данные профиля Telegram

## Когда использовать

Нужны данные профиля Telegram: имя, фото, bio, Premium, дата рождения, личный канал, или изменение профиля своего бота либо разрешенного аккаунта.

## Когда не использовать

История и сообщения пользовательского аккаунта — telegram-user-client. Права на объекты сервиса — telegram-python-backend.

## Алгоритм

Определите, чей профиль нужен и какая авторизованная сущность получает данные: обычный бот, подключенный business bot или пользовательский клиент. Сначала прочитайте [references/profile-access.md](references/profile-access.md). Не устанавливайте пользовательскую сессию только ради поля, которое уже доступно боту.

С библиотекой awesome-telegram-patterns, если она уже есть в проекте: [профили и оформление своего бота](references/profiles.md).

Используйте устойчивый numeric ID; username может отсутствовать или измениться. Для MTProto правильно разрешайте entity/access hash поддерживаемой библиотекой. Разделяйте личность пользователя, профиль чата и данные bot account.

Поле в схеме может быть optional или недоступным из-за privacy, контекста и возможностей текущего API. Сохраняйте различие между неизвестным значением и подтвержденным отрицательным результатом. Записывайте источник и время, если данные используются для решения о доступе.

Фото, bio, Premium, emoji status, дату рождения и personal channel выбирайте по конкретной задаче. Флаг verified/premium и отображаемое имя не заменяют серверную роль или проверку владельца заказа. Если функция «проверить аккаунт» означает риск-оценку, покажите полученные факты и ограничения, не выводите надежность человека из аватара или подписки.

Для изменения профиля установите точную цель и новые значения. Собственный бот, подключенный Business-аккаунт и MTProto user session используют разные методы и права; выберите маршрут из reference. Изменяйте только запрошенные поля, учитывайте language_code для локализованного описания бота и не превращайте пропуск поля в его очистку. После операции повторно получите доступные данные и обновите кеш; сетевой timeout не доказывает неуспех.

Телефон и скрытые данные не извлекаются из одного username. При обработке явно переданного contact проверьте его привязку к инициатору, если это нужно сценарию. Не публикуйте полное содержимое профиля или контактов в диагностических логах.

## Проверка

Проверьте профиль без username/фото, отсутствующие optional-поля, недоступный peer, отсутствие нужного права изменения и обновление кеша после смены имени. Для живой проверки работайте только с указанными пользователем целями; создание навыка не означает вход в конкретный аккаунт.

## Типичные ошибки

- Ради одного поля, доступного боту, устанавливается пользовательская сессия MTProto.
- Пользователь определяется по username, который может отсутствовать или смениться.
- Неизвестное значение смешивается с подтвержденным отрицательным: скрытое поле считается пустым.
- Premium, отметка verified или имя заменяют серверную роль и проверку владельца.
- Пропуск поля при изменении профиля превращается в его очистку; таймаут считается неуспехом.
