# Матрица реальных клиентов

Матрица выбирается по аудитории продукта и доступным устройствам. Размер окна, версия клиента и способ запуска важнее маркетингового названия устройства. Непроверенную платформу сохраняй в отчете, не превращай ее в успешную строку.

| Среда | Что наблюдать |
| --- | --- |
| Android Telegram | Клавиатура, системный возврат, insets, жесты, background/resume |
| iPhone Telegram | Клавиатура, вырезы/нижняя область, прокрутка формы, возврат, размер текста |
| iPad/Android tablet | Портрет/альбом, доступная ширина, split view, внешняя клавиатура по необходимости |
| Telegram Desktop/macOS | Resize до узкого окна, мышь/клавиатура, focus и поддержка нужных native API |
| Telegram Web | Запуск в поддерживаемом браузере, история/возврат и ограничения capabilities |

## Основной путь

1. Холодный запуск выбранным способом, прямая загрузка вложенного route, корректная готовность UI.
2. Выбор объекта, загрузка деталей, основной переход без потерянного состояния.
3. Форма: ввод, ошибки валидации, настоящая клавиатура, прокрутка к полю и действию. При внешней клавиатуре — порядок Tab и видимый focus.
4. Native/экранный Back, тема, доступный размер окна/поворот: данные сохраняются по смыслу сценария.
5. Сворачивание и возврат: UI получает актуальный snapshot, данные перепроверяются по необходимости, нет повторных listeners или операции.
6. Ошибка сети/истекшая сессия и восстановление. Повтор или двойное нажатие не создают второй серверный объект.

Если используются MainButton/SecondaryButton, их visibility, enabled, pending и результат согласованы с формой. Insets учитываются одним владельцем; системная и Telegram области не суммируются наугад. Capability проверяется по версии и фактической доступности, а не названию ОС.

## Запись результата

Для строки отчета достаточно: case id; build; устройство/ОС/Telegram; bridge version; launch mode; шаги; expected/observed; status; screenshot/video/log с очищенными данными; ограничение. У отказа должна быть воспроизводимая причина, у blocked — недостающий доступ/среда.

DevTools с device emulation, resize до 390×420 и synthetic pagehide полезны для диагностики, но не моделируют полностью клавиатуру, Telegram UI, BFcache и аппаратную производительность. После восстановления страницы отдельно проверь подписки и snapshot. Не меняй устройство/клиент в процессе сравнения без фиксации этого в отчете.

Источник: [viewport, события, safe areas и client APIs](https://core.telegram.org/bots/webapps#initializing-mini-apps).
