# Визуальные регрессии Mini App

Изучи существующий runner и способ запуска frontend. Используй текущий инструмент, если он умеет сравнивать изображения; Playwright — подходящий вариант при отсутствии выбора. Не заменяй тестовый стек и не создавай отдельный сервис ради нескольких snapshots.

## Воспроизводимый экран

Для baseline и различий прочитай [references/snapshots.md](references/snapshots.md). Зафиксируй браузер, ОС, шрифты, viewport, scale, тему, locale, данные и время. Fake Telegram adapter включается явно и воспроизводит только необходимые сигналы, не подменяя production bridge.

Дождись готового состояния экрана и шрифтов по наблюдаемым условиям. Отключай декоративное движение для стабильного снимка; поведение движения проверяй отдельным сценарием. Loading/error снимай через контролируемый ответ, а не случайный timeout.

Выбери матрицу по риску изменения: компактный и широкий layout, обе темы, длинный текст, затронутые состояния. Для нового общего shell добавь планшет/узкое desktop окно и малую высоту. Browser resize не моделирует реальную Telegram-клавиатуру.

## Сравнение

Эталон должен быть визуально просмотрен. При первом запуске отсутствие baseline означает необходимость его согласования; файл actual сам по себе не является passed проверкой.

Сохраняй expected/actual/diff и отчет. Порог учитывает особенности среды; не увеличивай его ради скрытия нового дефекта. Mask применяется к действительно переменным областям и не закрывает CTA, ошибку или измененный компонент.

Обновляй baseline только для подтвержденного изменения дизайна после просмотра diff. CI не должен автоматически принимать любое новое изображение. Нельзя признать измененный экран корректным только потому, что тест успешно перезаписал эталон.

## Проверка

Запусти сравнение, затем внеси контролируемый видимый дефект во временную копию и убедись, что тест обнаруживает его. Верни копию к baseline и повтори затронутую проверку. При реализации тестов добавь typecheck/проверку runner по проекту.

Укажи число фактически проверенных сочетаний, среду и исключения. Pixel diff ловит изменения, но не оценивает красоту, доступность, успешность операции или native bridge.
