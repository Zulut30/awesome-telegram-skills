# Визуальные регрессии Mini App

Изучите существующий runner и способ запуска frontend. Используйте текущий инструмент, если он умеет сравнивать изображения; Playwright — подходящий вариант при отсутствии выбора. Не заменяйте тестовый стек и не создавайте отдельный сервис ради нескольких snapshots.

## Воспроизводимый экран

Для baseline и различий прочитайте [references/snapshots.md](references/snapshots.md). Зафиксируйте браузер, ОС, шрифты, viewport, scale, тему, locale, данные и время. Fake Telegram adapter включается явно и воспроизводит только необходимые сигналы, не подменяя production bridge.

Дождитесь готового состояния экрана и шрифтов по наблюдаемым условиям. Отключайте декоративное движение для стабильного снимка; поведение движения проверяйте отдельным сценарием. Loading/error снимайте через контролируемый ответ, а не случайный timeout.

Выберите матрицу по риску изменения: компактный и широкий layout, обе темы, длинный текст, затронутые состояния. Для нового общего shell добавьте планшет/узкое desktop окно и малую высоту. Browser resize не моделирует реальную Telegram-клавиатуру.

## Сравнение

Эталон должен быть визуально просмотрен. При первом запуске отсутствие baseline означает необходимость его согласования; файл actual сам по себе не является passed проверкой.

Сохраняйте expected/actual/diff и отчет. Порог учитывает особенности среды; не увеличивайте его ради скрытия нового дефекта. Mask применяется к действительно переменным областям и не закрывает CTA, ошибку или измененный компонент.

Обновляйте baseline только для подтвержденного изменения дизайна после просмотра diff. CI не должен автоматически принимать любое новое изображение. Нельзя признать измененный экран корректным только потому, что тест успешно перезаписал эталон.

## Проверка

Запустите сравнение, затем внесите контролируемый видимый дефект во временную копию и убедитесь, что тест обнаруживает его. Верните копию к baseline и повторите затронутую проверку. При реализации тестов добавьте typecheck/проверку runner по проекту.

Укажите число фактически проверенных сочетаний, среду и исключения. Pixel diff ловит изменения, но не оценивает красоту, доступность, успешность операции или native bridge.
