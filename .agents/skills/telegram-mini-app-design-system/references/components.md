# Контракты компонентов

Токены задают роли вроде text, muted, surface, action, danger, border и focus. Их значения проверяются отдельно для светлой/темной темы и состояний. Одинаковый hex по всему приложению не заменяет семантику. Telegram themeParams могут приходить частично; fallback относится к визуальному оформлению и не создает fake launch/auth.

| Компонент | Существенное поведение |
| --- | --- |
| Button | HTML button с правильным type; имя, disabled/pending и единственное действие; link сохраняет навигационную семантику |
| Field | Label, значение у владельца формы, help/error связь, appropriate inputmode/autocomplete, сохранение focus/selection при вводе |
| Selectable card | Семантика radio/checkbox/link по действию, label как цель касания, состояние различимо без одного цвета |
| Dialog | Доступное имя, осмысленный начальный focus, закрытие, удержание focus при настоящей модальности и возврат к инициатору |
| Feedback | Разные loading/empty/error/success; повтор по смыслу операции, объявление значимого изменения без постоянного шума |

Не делайте кликабельный div универсальной заменой button. Для нестандартного widget потребуются его клавиатурные взаимодействия; обычные HTML controls часто проще и надежнее. `aria-disabled` само по себе не блокирует handler. Заблокированное действие должно объясняться пользователю.

Обычный текст ориентируйте на contrast 4.5:1, крупный — 3:1 по применимым правилам; focus и границы оцениваются отдельно. Если цвета анимируются при смене темы, проверьте пару текст/фон и в промежуточных состояниях: новый текст поверх еще старого фона может потерять контраст. Touch target 44 CSS px — практический ориентир этого набора, а не утверждение, что WCAG требует 44 px для любого элемента. Для hidden radio измеряется действующая область label.

В галерее покажите реальные состояния нужных компонентов, обе темы и container шириной около 320 px плюс широкий режим. Проверьте длинный перевод, error, pending, пустое значение и reduced motion. Поле должно позволять продолжать ввод после render, а dialog — закрываться и возвращать focus.

В продукте один владелец primary action связывает UI-кнопку и native MainButton. Набор компонентов не инициирует отправку сам по себе и не доказывает серверную однократность операции. Изменение визуального состояния не очищает введенные данные.

Источники: [Modal dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/), [contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).
