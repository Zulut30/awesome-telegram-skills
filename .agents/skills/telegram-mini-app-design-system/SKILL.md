# Компоненты и дизайн-токены

Сначала изучи существующие компоненты, бренд и frontend framework. Если библиотека уже решает задачу, расширь ее. Выделяй повторяемые компоненты по реальным экранам; новый monorepo, Storybook и публикация npm package не обязательны.

## Токены и контракт

Для состояний и проверки компонентов прочитай [references/components.md](references/components.md). Определи семантические токены цвета, текста, расстояний, границ, радиусов и движения. Свяжи их с Telegram themeParams через один adapter и предусмотренное оформление вне Telegram. При смене темы значения обновляются без сброса состояния формы.

Компонент имеет ясный публичный контракт: данные, событие действия, варианты и состояния. Прикладные цены, права, auth и API-запросы остаются у владельца сценария. Общее поле или кнопка не должны читать window.Telegram либо хранить второй экземпляр server state.

## Поведение

Используй подходящую HTML-семантику. У полей есть labels и связанные ошибки; у кнопок — доступное имя; focus виден в обеих темах. Pending отражает настоящее состояние операции; повторная активация блокируется согласованно с native действием, если оно есть.

Для dialog/popover выбери семантику по взаимодействию; проверь открытие, закрытие, focus и клавиатуру. Insets и основная геометрия принадлежат shell: компонент не добавляет ту же safe area повторно. Длинные подписи и compact/wide layout не должны обрезать действие.

Motion tokens имеют режим reduced motion; действие и cleanup не зависят только от animationend. Изменение темы/размера не перехватывает focus. Проверку screen reader фиксируй по фактической среде: automated scan и наличие ARIA не являются доказательством целевого reader.

## Приемка

Собери небольшую доступную галерею только нужных компонентов/состояний или существующие stories. Проверь ее визуально в двух темах, узком и широком контейнере, с длинными строками, touch и клавиатурой. Проверь контраст и реальные кликабельные области; CSS классы не доказывают доступность.

Подключи компоненты хотя бы к одному реальному экрану и проверь прежний путь. Сохрани typecheck/build, screenshots и документированный контракт. Размер и зависимости библиотеки должны соответствовать ее использованию.

Источники: [Telegram Design Guidelines](https://core.telegram.org/bots/webapps#design-guidelines), [WAI-ARIA patterns](https://www.w3.org/WAI/ARIA/apg/patterns/), [WCAG contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).
