# Компоненты и дизайн-токены

Сначала изучите существующие компоненты, бренд и frontend framework. Если библиотека уже решает задачу, расширь ее. Выделяйте повторяемые компоненты по реальным экранам; новый monorepo, Storybook и публикация npm package не обязательны.

## Токены и контракт

Для состояний и проверки компонентов прочитайте [references/components.md](references/components.md). Определите семантические токены цвета, текста, расстояний, границ, радиусов и движения. Свяжите их с Telegram themeParams через один adapter и предусмотренное оформление вне Telegram. При смене темы значения обновляются без сброса состояния формы.

Компонент имеет ясный публичный контракт: данные, событие действия, варианты и состояния. Прикладные цены, права, auth и API-запросы остаются у владельца сценария. Общее поле или кнопка не должны читать window.Telegram либо хранить второй экземпляр server state.

## Поведение

Используйте подходящую HTML-семантику. У полей есть labels и связанные ошибки; у кнопок — доступное имя; focus виден в обеих темах. Pending отражает настоящее состояние операции; повторная активация блокируется согласованно с native действием, если оно есть.

Для dialog/popover выберите семантику по взаимодействию; проверьте открытие, закрытие, focus и клавиатуру. Insets и основная геометрия принадлежат shell: компонент не добавляет ту же safe area повторно. Длинные подписи и compact/wide layout не должны обрезать действие.

Motion tokens имеют режим reduced motion; действие и cleanup не зависят только от animationend. Изменение темы/размера не перехватывает focus. Проверку screen reader фиксируйте по фактической среде: automated scan и наличие ARIA не являются доказательством целевого reader.

## Приемка

Соберите небольшую доступную галерею только нужных компонентов/состояний или существующие stories. Проверьте ее визуально в двух темах, узком и широком контейнере, с длинными строками, touch и клавиатурой. Проверьте контраст и реальные кликабельные области; CSS классы не доказывают доступность.

Подключите компоненты хотя бы к одному реальному экрану и проверьте прежний путь. Сохраните typecheck/build, screenshots и документированный контракт. Размер и зависимости библиотеки должны соответствовать ее использованию.
