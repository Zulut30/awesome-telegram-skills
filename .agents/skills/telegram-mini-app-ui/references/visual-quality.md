# Визуальное качество

Для нового продукта выберите короткое направление по задаче и аудитории. Красота выражается в согласованной системе, читаемости и понятном действии. Для существующего продукта сохраняйте его компоненты и стиль.

## Система

Определите semantic tokens: surface/background, текст, action, border, error; небольшой набор размеров текста, spacing и radii. Telegram themeParams проходят через tokens, включая смену темы во время формы. Бренд допустим при достаточном контрасте.

У экрана есть заголовок, иерархия и заметное основное действие. Ограничивайте строки и форму на desktop. Обзор рядом с формой на tablet/desktop не дублирует состояние. Компоненты имеют согласованные focus, selected, disabled, pending и error. Не заменяйте label placeholder и не прячьте инструкцию за hover.

## Доступность

Для обычного текста ориентир WCAG AA — contrast 4.5:1; для крупного — 3:1 по определению стандарта. Проверяйте реальные цвета обеих тем; прозрачность влияет на результат. Два коэффициента не являются полным WCAG audit.

Для основных touch controls отправной размер 44×44 CSS px с интервалами — критерий удобства набора, не универсальный минимум WCAG AA. WCAG 2.2 Target Size (Minimum) задает 24×24 с исключениями/spacing. Маленькая иконка может иметь большую область нажатия.

Используйте настоящие `button`, `input` и `a`, подписи `label`, доступные имена, переход по Tab и видимый фокус. Выбор карточки должен озвучиваться экранным диктором. Для диалога проверьте перенос фокуса внутрь и возврат обратно, закрытие по Escape и кнопке «Назад» и недоступность перекрытого содержимого.

Ошибка рядом с полем дает путь исправления; временная ошибка не стирает ввод. Loading не блокирует все без необходимости, подтверждение объясняет результат. Существенные анимации учитывают reduced motion; эффект не является условием навигации.

## Визуальная приемка

Откройте screenshots компактного и широкого состояния в обеих темах. Проверьте иерархию, выравнивание, переносы, плотность, CTA, перекрытия и состояния. Исправляйте конкретный дефект и повторяйте затронутый путь. Overflow check не оценивает красоту или понятность.

Без рендера назовите ограничение и дайте воспроизводимый сценарий; CSS не доказывает визуальную проверку. Субъективную оценку отделяйте от измеренного контраста и поведения.

Источники: [Telegram Design Guidelines](https://core.telegram.org/bots/webapps#design-guidelines), [W3C contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [W3C target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), [reduced motion](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion).
