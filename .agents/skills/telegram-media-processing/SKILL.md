# Обработка Telegram-медиа

Определи источник файла, целевой формат и необходимый результат. Сохраняй исходный SDK/storage и выбирай обработчик по формату; FFmpeg, Pillow, очередь и локальный Bot API server нужны только по задаче. Не устанавливай сервисы глобально ради примера.

## Прием и преобразование

Для файловых границ, jobs и Telegram ID прочитай [references/pipeline.md](references/pipeline.md). Проверяй разрешенный тип по содержимому выбранным parser; имя, расширение и заявленный MIME недостоверны. Установи лимиты входа, размеров/длительности, распаковки, output, времени и параллелизма по продукту.

Сохраняй файл в контролируемом временном каталоге под серверным именем. Пользовательский путь/URL не передается процессу как доверенный источник. Не собирай shell-команду из имени файла; запускай обработчик аргументами и ограничивай чтение/сеть по среде.

Превью и перекодирование учитывают ориентацию, пропорции, звук и метаданные. Не растягивай изображение и не превращай документ в изображение по умолчанию. Удаляй приватные метаданные только по согласованной цели, сохраняя полезную ориентацию результата.

## Задача и выдача

Долгую обработку отделяй от Telegram handler/HTTP ответа по необходимости. Job имеет owner scope, input reference/hash, transform version и ясные queued/running/ready/failed/canceled. Перезапуск не должен создавать второй расходный output или повторную отправку без политики доставки.

Готовый результат доступен только разрешенному пользователю, независимо от угадываемого job ID. Отмена останавливает/завершает процесс по контракту и удаляет временные файлы; поздний worker не публикует отмененный результат.

Для Telegram повторного использования сохраняй полученный file_id вместе с bot scope и видом media. file_unique_id полезен для связи, но не для скачивания/отправки. Сверяй актуальные лимиты метода и hosted/local Bot API, не обещая один размер для всех путей.

## Проверка

Испытай настоящий маленький файл, подмененный MIME, поврежденный файл, превышение лимита и restart/cancel. Проверь output parser/длительность/размер, очистку и доступ другого пользователя. Fake sender не является live Telegram upload.

Запусти новый helper/process на временном файле, если он добавлен; unit-тест строки команды не подтверждает преобразование. Если codec/tool недоступен, сохрани конкретное ограничение и воспроизводимый шаг без заявления об успешной обработке.

Источники: [Telegram Bot API](https://core.telegram.org/bots/api), [FFmpeg documentation](https://ffmpeg.org/documentation.html), [OWASP File Upload](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html).
