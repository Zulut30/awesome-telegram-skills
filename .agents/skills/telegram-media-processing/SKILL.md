# Обработка Telegram-медиа

## Когда использовать

Бот или Mini App принимает и обрабатывает файлы: проверка фото, видео, аудио и документов, преобразование, превью, фоновые задания, повторное использование `file_id`.

## Когда не использовать

Отправка уже готового файла — telegram-bot-api. Медиа в общей библиотеке компонентов — telegram-code-patterns.

## Алгоритм

Определите источник файла, целевой формат и необходимый результат. Сохраняйте исходный SDK/storage и выбирайте обработчик по формату; FFmpeg, Pillow, очередь и локальный Bot API server нужны только по задаче. Не устанавливайте сервисы глобально ради примера.

### Прием и преобразование

Для файловых границ, jobs и Telegram ID прочитайте [references/pipeline.md](references/pipeline.md). Проверяйте разрешенный тип по содержимому выбранным parser; имя, расширение и заявленный MIME недостоверны. Установите лимиты входа, размеров/длительности, распаковки, output, времени и параллелизма по продукту.

Сохраняйте файл в контролируемом временном каталоге под серверным именем. Пользовательский путь/URL не передается процессу как доверенный источник. Не собирайте shell-команду из имени файла; запускайте обработчик аргументами и ограничивайте чтение/сеть по среде.

Превью и перекодирование учитывают ориентацию, пропорции, звук и метаданные. Не растягивайте изображение и не превращайте документ в изображение по умолчанию. Удаляйте приватные метаданные только по согласованной цели, сохраняя полезную ориентацию результата.

### Задача и выдача

Долгую обработку при необходимости отделяйте от обработчика Telegram и HTTP-ответа. У задания есть владелец, ссылка на входной файл или его хеш, версия преобразования и ясные статусы `queued`, `running`, `ready`, `failed`, `canceled`. Перезапуск не должен создавать второй расходный output или повторную отправку без политики доставки.

Готовый результат доступен только разрешенному пользователю, независимо от угадываемого job ID. Отмена останавливает/завершает процесс по контракту и удаляет временные файлы; поздний worker не публикует отмененный результат.

Для Telegram повторного использования сохраняйте полученный file_id вместе с bot scope и видом media. file_unique_id полезен для связи, но не для скачивания/отправки. Сверяйте актуальные лимиты метода и hosted/local Bot API, не обещая один размер для всех путей.

## Проверка

Испытайте настоящий маленький файл, подмененный MIME, поврежденный файл, превышение лимита и restart/cancel. Проверьте output parser/длительность/размер, очистку и доступ другого пользователя. Fake sender не является live Telegram upload.

Запустите новый helper/process на временном файле, если он добавлен; unit-тест строки команды не подтверждает преобразование. Если codec/tool недоступен, сохраните конкретное ограничение и воспроизводимый шаг без заявления об успешной обработке.

## Типичные ошибки

- Тип файла определяется по имени, расширению или заявленному MIME.
- Shell-команда собирается из имени файла пользователя.
- Перезапуск задания создает второй результат или повторную отправку.
- Результат доступен любому, кто угадал ID задания.
- `file_unique_id` используется для скачивания или отправки, а `file_id` хранится без привязки к боту.
