# Crypto Pay / CryptoBot

Определи товар, платежный маршрут и среду. Сначала проверь применимость внешней оплаты по актуальным требованиям Telegram. Затем прочитай [references/crypto-pay.md](references/crypto-pay.md). Crypto Pay token относится к платежному приложению, отдельно от bot token.

Создай server-side adapter выбранной библиотеки или HTTPS API. Сохраняй локальный заказ и provider invoice ID до выдачи ссылки. Передавай непрозрачную связь с заказом в payload; привязку к пользователю бери из серверного заказа. Не определяй покупателя по комментарию плательщика.

Проверяй сумму и выбранный режим валюты без float. Различай номинал заказа, фактически уплаченный asset и удержанную комиссию. Платеж в другой допустимой криптовалюте не следует сравнивать с номиналом без контекста режима invoice.

Webhook adapter сначала проверяет подпись и формат, затем связывает invoice с заказом. Сверяй авторитетное состояние через provider API по потребности. Уникальность выдачи обеспечивается по provider + invoice + прикладной операции; не используй webhook update ID как единственный deduplication key.

Храни payment attempts и выполняй переход заказа с выдачей или outbox атомарно. Сбой после оплаты должен восстанавливаться reconciliation-задачей. После timeout создания invoice результат неизвестен: не создавай второй invoice автоматически без проверки сохраненного attempt.

Возврат или transfer — отдельная финансовая операция с собственными условиями, доступами и защитой от повторов. Не обещай универсальный refund endpoint без подтверждения его наличия в текущей версии.

Проверь testnet create/status, неверную подпись, повтор webhook, несовпадение заказа, позднюю оплату и восстановление после потерянного уведомления. При отсутствии credentials подготовь adapter и изолированные тесты; живую оплату не считай выполненной.
