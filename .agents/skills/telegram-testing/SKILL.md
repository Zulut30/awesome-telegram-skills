# Проверка бота и Mini App

Определи, какое поведение изменилось и какой отказ опасен для пользователя. Используй существующий тестовый стек. Для маленького обратимого UI-изменения может хватить сборки и ручного сценария; для авторизации, платежей и целостности состояния нужны проверки соответствующих инвариантов.

## Уровни проверки

- Прикладные операции проверяй без сети: цены, доступ, переходы, повторное выполнение.
- Обработчики проверяй synthetic updates и fake transport установленной библиотеки. Они должны подтверждать результат и исходящие действия, а не только факт вызова handler.
- Интеграции проверяй с реальным storage и HTTP-контрактом там, где mock скрывает риск: транзакции, конкурентные изменения, durable acceptance webhook.
- WebView и доставку Telegram проверяй на отдельном тестовом боте. Браузерный mock bridge не подтверждает работу внутри Telegram.

## Выбрать значимые случаи

| Изменение | Наблюдаемый инвариант |
| --- | --- |
| Webhook или обработка update | Повтор доставки не повторяет операцию; сбой до надежного приема не теряет ее |
| Диалог | Пользователи изолированы; старая кнопка не меняет завершенный объект |
| Mini App auth | Измененные, просроченные и неоднозначные данные отклоняются; права проверяются отдельно |
| Платежи | Повторное подтверждение не удваивает выдачу; неверная сумма не выдает товар |
| UI | Действие доступно при клавиатуре, темной теме и маленьком viewport |

Добавляй только случаи, относящиеся к изменению. Для криптографии используй независимо полученный вектор. Для конкурентных операций моделируй реальную гонку, а не два последовательных вызова.

Для нового Mini App или существенного изменения его UI/архитектуры используй [references/mini-app-matrix.md](references/mini-app-matrix.md). Матрица проверяет наблюдаемое поведение, компоновку и сохранение состояния; снимки сравниваются визуально, а не по наличию определенных классов CSS.

## Работа с реальным ботом

Polling читает и подтверждает updates; не подключай второго потребителя к рабочему боту ради теста. Изолируй тестовые token, chat, storage и платежную среду. Не запускай платеж или сообщение в чужой чат как побочный эффект проверки без авторизации на такой сценарий.

## Результат

Запиши проверенную версию, среду и наблюдаемый результат. Отдельно назови прошедшие offline-проверки, runtime-проверки и оставшиеся ограничения. Если нет доступа к Telegram, подготовь воспроизводимый runtime-сценарий и не заявляй, что интеграция работает.

## Источники

[Bot API](https://core.telegram.org/bots/api), [тестовая среда Mini Apps](https://core.telegram.org/bots/webapps#using-bots-in-the-test-environment). Для поведения transport используй документацию библиотеки проекта.
