# Ветки платежей

## Цифровые товары и услуги

Источник: [Telegram Stars](https://core.telegram.org/bots/payments-stars).

Для цифровых покупок внутри Telegram используйте Stars (`XTR`). Проверьте правила `provider_token`, состава prices и invoice выбранного метода. Ответ на `pre_checkout_query` требуется в течение 10 секунд. Подтверждение выдачи — серверное событие с `successful_payment`, а не нажатие пользователя.

Сохраняйте `telegram_payment_charge_id`; для возврата Stars есть `refundStarPayment`. Предусмотрите `/paysupport` и пользовательскую поддержку по актуальным требованиям Telegram. Не обещайте курс вывода, комиссию или доступность страны без текущей проверки.

До покупки предоставьте понятные условия через `/terms` либо столь же доступный путь и получите подтверждение согласия пользователя: это требование [Live Checklist](https://core.telegram.org/bots/payments-stars#live-checklist). Версию принятых условий можно сохранять в заказе по модели продукта; сам навык не задает юридический текст. Поддержка и `/paysupport` остаются отдельными каналами.

Для Stars-подписок проверьте `subscription_period`, доступные методы, события продления и отмены в текущем API и SDK. Не переноситесь к механике карточного провайдера из другой ветки.

## Физические товары и услуги

Источник: [Bot Payments API](https://core.telegram.org/bots/payments).

Проверьте поддерживаемого провайдера, currency, minor units, provider token и ограничения страны. Shipping и order info подключайте только по требованиям продукта. Успешный pre-checkout еще не означает полученную оплату. Возвраты и рекуррентные операции выполняйте по правилам конкретного провайдера; `refundStarPayment` не является API возврата карточного платежа.

## Работа из Mini App

Клиент открывает выданный сервером invoice и показывает UX процесса. Право на товар определяется сохраненным серверным платежным фактом. Если checkout закрылся, а update пришел позднее, frontend должен уметь получить актуальный статус заказа.

Методы и поля: [Bot API](https://core.telegram.org/bots/api). Проверяйте их по установленной версии SDK; платежные политики требуют текущей проверки официального источника.
