# Работа с Bot API

Найди требуемый метод в актуальной официальной документации и сопоставь его с версией SDK в проекте. Не изобретай параметры по похожим именам. Если SDK отстает, сначала оцени совместимый вызов существующим клиентом; обновление всей библиотеки требует учета его последствий.

Для обзора возможностей прочитай [references/features.md](references/features.md). Для поиска точного метода, типа или поля используй [references/api-index.json](references/api-index.json) по ключевому слову; не загружай весь индекс в контекст без необходимости. Индекс включает имена и поля, а ограничения и семантику нужно читать по официальной ссылке найденной записи.

Обновление снимка без credentials: `python scripts/update_api_index.py` из каталога этого навыка. Проверь дату, version и diff индекса; изменение имени поля не доказывает поддержку новой версии SDK.

С библиотекой awesome-telegram-patterns, если она уже есть в проекте: [текст и entities](references/message-text.md), [медиа](references/media.md), [опросы и quiz](references/polls.md). Пакет для навыка не обязателен.

## Построить операцию

Определи входной update, доступный тип чата, необходимые поля и ожидаемый ответ. Поля `message`, `text`, `from` и данные callback могут отсутствовать. Не делай обработчик одного типа update универсальным разборщиком всех событий.

Перед формированием сообщения выбери entities или поддерживаемый parse mode; экранируй пользовательские вставки согласно этому режиму. Проверь актуальные лимиты выбранного метода, особенно для media, captions и callback data. Если используешь entities, учитывай UTF-16 offsets.

Не помещай полномочия или чувствительные данные в callback payload. Перед изменением объекта проверь, что нажимающий пользователь имеет доступ к нему. Своевременно отвечай на callback query, а длительную прикладную работу выполняй отдельно.

## Доставка и ошибки

Polling и webhook взаимоисключающие. Тестовое окружение Telegram отдельное: свой аккаунт, бот и токен, запросы на `https://api.telegram.org/bot<token>/test/METHOD_NAME`; токен основного бота там не действует. Повторно полученный update не должен повторять прикладной эффект. При `429` используй `retry_after`; при сетевом таймауте после отправки результат может быть неизвестен. Не повторяй необратимую операцию вслепую.

Различай ошибку входных параметров, нехватку прав, недоступность чата и временную сетевую ошибку. Используй поля `ResponseParameters`, когда они доступны. В логах скрывай токен, включая URL запросов и скачивания файлов.

## Проверка

Проверь сериализованный запрос и обработку ответа на уровне существующих тестов. Для пользовательской функции выполни один реальный сценарий на тестовом боте, если есть доступ. Укажи проверенный тип чата и отдельно отметь непроверенные платформы или права.
