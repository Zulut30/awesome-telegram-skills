# Работа с Bot API

Найдите требуемый метод в актуальной официальной документации и сопоставьте его с версией SDK в проекте. Не изобретайте параметры по похожим именам. Если SDK отстает, сначала оцените совместимый вызов существующим клиентом; обновление всей библиотеки требует учета его последствий.

Для обзора возможностей прочитайте [references/features.md](references/features.md). Для поиска точного метода, типа или поля используйте [references/api-index.json](references/api-index.json) по ключевому слову; не загружайте весь индекс в контекст без необходимости. Индекс включает имена и поля, а ограничения и семантику нужно читать по официальной ссылке найденной записи.

Обновление снимка без credentials: `python scripts/update_api_index.py` из каталога этого навыка. Проверьте дату, version и diff индекса; изменение имени поля не доказывает поддержку новой версии SDK.

С библиотекой awesome-telegram-patterns, если она уже есть в проекте: [текст и entities](references/message-text.md), [медиа](references/media.md), [опросы и quiz](references/polls.md). Пакет для навыка не обязателен.

## Построить операцию

Определите входной update, доступный тип чата, необходимые поля и ожидаемый ответ. Поля `message`, `text`, `from` и данные callback могут отсутствовать. Не делайте обработчик одного типа update универсальным разборщиком всех событий.

Перед формированием сообщения выберите entities или поддерживаемый parse mode; экранируйте пользовательские вставки согласно этому режиму. Проверьте актуальные лимиты выбранного метода, особенно для media, captions и callback data. Если используешь entities, учитывайте UTF-16 offsets.

Не помещайте полномочия или чувствительные данные в callback payload. Перед изменением объекта проверьте, что нажимающий пользователь имеет доступ к нему. Своевременно отвечайте на callback query, а длительную прикладную работу выполняйте отдельно.

## Доставка и ошибки

Polling и webhook взаимоисключающие. Тестовое окружение Telegram отдельное: свой аккаунт, бот и токен, запросы на `https://api.telegram.org/bot<token>/test/METHOD_NAME`; токен основного бота там не действует. Повторно полученный update не должен повторять прикладной эффект. При `429` используйте `retry_after`; при сетевом таймауте после отправки результат может быть неизвестен. Не повторяйте необратимую операцию вслепую.

Различайте ошибку входных параметров, нехватку прав, недоступность чата и временную сетевую ошибку. Используйте поля `ResponseParameters`, когда они доступны. В логах скрывайте токен, включая URL запросов и скачивания файлов.

## Проверка

Проверьте сериализованный запрос и обработку ответа на уровне существующих тестов. Для пользовательской функции выполните один реальный сценарий на тестовом боте, если есть доступ. Укажите проверенный тип чата и отдельно отметьте непроверенные платформы или права.
