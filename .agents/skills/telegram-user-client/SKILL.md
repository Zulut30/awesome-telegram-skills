# Пользовательский клиент Telegram

Определите задачу, аккаунт, выбранные чаты, глубину истории и направление работы. Для чтения dialogs и истории аккаунта в Python отправной вариант — Telethon; для ограниченного доступа к подключенным business chats сначала оцените официальный Business/Secretary Bot.

Прочитайте [references/telethon.md](references/telethon.md). Bot token в MTProto дает бот-идентичность, а не доступ к чатам пользователя. Для разработки без аккаунта подготовьте код и fake client; авторизацию выполняйте только в рамках отдельно порученного входа.

Сохраняйте прикладную логику отдельно от Telethon event objects. Для чтения истории задайте allowlist чатов, диапазон, пагинацию и checkpoint по peer/message ID. При совмещении истории с live updates устрани разрыв и дубли между ними.

При reconnect учитывайте повторные события, edits и deletes согласно задаче. Ограничивайте параллелизм и обрабатывайте FloodWait по времени сервера. Не обходите ограничения сменой аккаунтов или повторным входом в цикле.

Чтение истории не должно незаметно включать отправку сообщений, вступление в группы, отметку read или выгрузку всех контактов. Добавляйте такие действия только по конкретному сценарию. Не обещайте доступ к secret chats обычным cloud-history вызовом.

Session-файлы и StringSession содержат полномочия аккаунта. Храните их отдельно от исходников с ограниченным доступом, не отправляйте в логи или пользователю. Обеспечьте disconnect и понятное поведение после отзыва сессии.

Проверьте filtered history, повтор события, checkpoint/reconnect и недоступный chat на fake client. При наличии авторизованной тестовой сессии проверьте один выбранный чат без публикации его содержимого. Отметьте отдельно offline- и live-результат.
