# Пользовательский клиент Telegram

Определи задачу, аккаунт, выбранные чаты, глубину истории и направление работы. Для чтения dialogs и истории аккаунта в Python отправной вариант — Telethon; для ограниченного доступа к подключенным business chats сначала оцени официальный Business/Secretary Bot.

Прочитай [references/telethon.md](references/telethon.md). Bot token в MTProto дает бот-идентичность, а не доступ к чатам пользователя. Для разработки без аккаунта подготовь код и fake client; авторизацию выполняй только в рамках отдельно порученного входа.

Сохраняй прикладную логику отдельно от Telethon event objects. Для чтения истории задай allowlist чатов, диапазон, пагинацию и checkpoint по peer/message ID. При совмещении истории с live updates устрани разрыв и дубли между ними.

При reconnect учитывай повторные события, edits и deletes согласно задаче. Ограничивай параллелизм и обрабатывай FloodWait по времени сервера. Не обходи ограничения сменой аккаунтов или повторным входом в цикле.

Чтение истории не должно незаметно включать отправку сообщений, вступление в группы, отметку read или выгрузку всех контактов. Добавляй такие действия только по конкретному сценарию. Не обещай доступ к secret chats обычным cloud-history вызовом.

Session-файлы и StringSession содержат полномочия аккаунта. Храни их отдельно от исходников с ограниченным доступом, не отправляй в логи или пользователю. Обеспечь disconnect и понятное поведение после отзыва сессии.

Проверь filtered history, повтор события, checkpoint/reconnect и недоступный chat на fake client. При наличии авторизованной тестовой сессии проверь один выбранный чат без публикации его содержимого. Отметь отдельно offline- и live-результат.
