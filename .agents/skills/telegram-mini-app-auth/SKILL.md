# Аутентификация Mini App

Проверь точку запуска и формат данных, которые frontend действительно получает. Схему подписи сверяй с [references/validation.md](references/validation.md). Это аутентификация Mini App; не подменяй ее алгоритмом Telegram Login Widget или OIDC.

## Вход на backend

Передавай исходную строку `initData` на сервер по HTTPS. Для доступа проверяй подпись, выбранный bot/environment и свежесть данных. `initDataUnsafe`, query-параметры страницы и переданный frontend `user_id` не устанавливают личность.

Предпочти поддерживаемый validator используемой библиотеки. Проверь, обеспечивает ли он freshness и строгий разбор; успешная HMAC-проверка сама по себе их не гарантирует. Для Python изучи функции aiogram WebApp utils, если aiogram уже присутствует. Не добавляй всю библиотеку только ради одного helper без оценки альтернатив.

Определи допустимый возраст и clock skew исходя из UX. При истечении предложи заново открыть Mini App или обновить серверную сессию. Чрезмерно короткий срок не должен ломать долгую форму без восстановления.

## Сессия и полномочия

После валидации извлекай личность из подписанных данных и загружай серверные права. Создай ограниченную серверную сессию по модели проекта. Для cookie-сессии проверь CSRF и поведение cookies в целевых WebView; для bearer-сессии ограничь срок и хранение.

Владение заказом, разрешение на действие и цена проверяются отдельно. Подпись не делает произвольное действие авторизованным. Не записывай токен, исходную initData или полное персональное содержимое в логи.

Повторное использование одной свежей initData может быть допустимо для создания сессии. Для одноразовых операций используй отдельный nonce или idempotency key; не выдавай HMAC за универсальную защиту от replay.

## Проверка

Проверь корректные данные, измененное подписанное поле, другой bot token, отсутствие hash/auth_date, дубли ключей, просроченную и будущую дату. Используй реальный обезличенный либо официальный тестовый вектор, а не только подпись, сгенерированную проверяемым кодом. Проверь, что клиентский user_id не меняет доступ к объекту.
