# Диалоги и состояние

Построй небольшую таблицу переходов: текущее состояние → допустимый ввод → проверка → действие → следующее состояние. Учти старт, отмену, возврат, таймаут и повторный вход. Для обычного меню не создавай FSM без необходимости.

## Ключи и долговечность

Выбери ключ по смыслу сценария: отдельный пользователь, пользователь в чате, пользователь в теме либо общий процесс группы. Разделяй временные ответы формы и долговечные бизнес-объекты. Укажи, должен ли диалог переживать рестарт и работать на нескольких экземплярах.

При конкурирующих updates сериализуй переходы одного диалога либо используй атомарную версию состояния. Переход, создающий заказ или запись, должен иметь защиту от повторного выполнения независимо от UI.

Для aiogram используй FSM установленной версии. Для python-telegram-bot проверь ConversationHandler, persistence и настройки concurrency. В другом framework используй существующий механизм; не мигрируй весь бот ради диалога.

## Кнопки и входные данные

Старые сообщения остаются доступными: callback должен проверять текущую версию процесса, владельца и допустимость действия. Просроченная кнопка должна давать понятный ответ, а не изменять уже завершенный объект.

Подтверждай callback через `answerCallbackQuery` установленного SDK, включая старую кнопку, отказ и повтор. Для длительной операции ответь до ее выполнения, не объявляя еще не сохраненный переход успешным. ACK убирает индикатор ожидания клиента; `sendMessage` или редактирование сообщения его не заменяют.

Не доверяй callback payload и тексту сообщения как полномочию. Валидируй каждый шаг на сервере. Команды отмены и помощи должны быть доступны там, где пользователь может застрять. На неожиданный тип сообщения сообщи ожидаемое действие без потери состояния.

Если операции длительные, покажи пользователю принятый запрос и предусмотренный продуктом способ узнать результат. Ограничивай сохраненные данные сроком, соответствующим сценарию.

## Проверка

Проверь успешный путь, отмену на промежуточном шаге, неверный ввод, два быстрых нажатия, старую кнопку и восстановление после рестарта, если оно обещано. Отдельно проверь, что два пользователя не разделяют ответы формы.

## Источники

[aiogram FSM](https://docs.aiogram.dev/en/latest/dispatcher/finite_state_machine/index.html), [python-telegram-bot](https://docs.python-telegram-bot.org/en/stable/), [CallbackQuery](https://core.telegram.org/bots/api#callbackquery). Используй только ветку библиотеки проекта.

Если проект уже использует локальную библиотеку awesome-telegram-patterns 0.18.0 и aiogram, [готовые mixed fields](references/dialog-fields.md) подключаются к текущему Dispatcher/FSM. Навык не требует установки библиотеки либо соседних навыков: при другом SDK сохраняй стек и реализуй те же author/step/reply и confirmation guards средствами проекта.
