# Выбор библиотек

## Когда использовать

Нужно выбрать библиотеку для нового бота, клиента или платежки, проверить незнакомый пакет, решить, поддерживает ли установленная версия новую функцию Telegram, или оценить миграцию с одной библиотеки на другую.

## Когда не использовать

Библиотека уже выбрана и нужно писать код — работайте по скиллу этой области. Подключение готовых компонентов этого репозитория — telegram-code-patterns.

## Алгоритм

1. **Плоскость API.** Определите, с чем работает код: Bot API (бот), MTProto (пользовательский аккаунт: Telethon, TDLib), мост WebApp (Mini App) или API платежного провайдера. Библиотека одной плоскости не заменяет другую.
2. **Существующий проект.** Оставьте текущую библиотеку, пока нет конкретной функции, которую она не может дать. На вопрос «мигрировать ли, потому что другая популярнее» отвечайте прямо: нет, популярность — не причина; сначала назовите функцию, которой не хватает, и проверьте ее в установленной версии **текущей** библиотеки (для python-telegram-bot — `pip show python-telegram-bot` и импорт нужного класса из `telegram`): часто она уже есть. Проверьте нужную функцию в **установленной** версии, а не в changelog Bot API: `pip show aiogram`, затем импорт метода или поля (`from aiogram.methods import SendMessageDraft`, `"style" in InlineKeyboardButton.model_fields`) и итоговую сериализацию. Версия Bot API на сайте не доказывает поддержку в SDK.
3. **Новый проект.** Сравните кандидатов таблицей по критериям, а не по звездам: модель выполнения (async или sync), поддерживаемые версии Python, дата последнего релиза и частота релизов, поддерживаемая версия Bot API, лицензия, встроенные состояние и планировщик. Приведите эту таблицу в ответе. Затем перечислите методы и поля, которые нужны проекту (для backend Mini App — `answerWebAppQuery`, `setChatMenuButton`, кнопка с `web_app`), и сверьте каждый с установленной версией выбранного SDK (шаг 2): таблица говорит о пакете, а не о вашей функции. Снимок на 7 октября 2026 года — в [references/libraries.md](references/libraries.md); перепроверьте его на PyPI. Если других требований нет, отправная точка для Python-бота — aiogram.
4. **Одна библиотека на роль.** Назовите конкретную совместимую версию и закрепите ее диапазоном (`aiogram>=3.31,<3.32`) или lock-файлом. Не ставьте вторую библиотеку Bot API рядом с первой.
5. **Происхождение пакета.** Различайте официальный API, официальный SDK поставщика и обертку сообщества. Похожее имя не доказывает принадлежность: страница PyPI должна вести на репозиторий, на который ссылается документация поставщика. Пакет из поисковой выдачи без такой связи не устанавливайте.
6. **Синхронный SDK в async-коде.** Прямой вызов из обработчика aiogram блокирует цикл событий. Выносите его в `asyncio.to_thread(...)` с таймаутом и ограничением параллельности или вызывайте API провайдера асинхронным HTTP-клиентом проекта.
7. **Миграция.** Если она нужна ради конкретной функции, учтите обработчики и фильтры, middleware, сохраненные состояния FSM или `persistence`, сессии, тесты и несовместимые изменения; переносите поэтапно и с проверкой на копии данных, а не заменой импортов.

## Пример результата

| Критерий | aiogram | python-telegram-bot | pyTelegramBotAPI |
| --- | --- | --- | --- |
| Модель | async | async | sync и async |
| Python | 3.10–3.14 | от 3.10 | от 3.10 |
| Последний релиз | 3.31.0, 26.08.2026 | 22.8, 12.06.2026 | 4.37.0, 21.09.2026 |
| Активность: релизов за 12 месяцев | 12 | 3 | 9 |
| Bot API | 10.3 | 10.0 | 10.3 |
| Лицензия | MIT | LGPL-3.0 | GPL-2.0 |

> Роль: Bot API для бота с backend Mini App. Выбор: aiogram, `aiogram>=3.31,<3.32` (Python 3.10–3.14, релиз 26.08.2026, Bot API 10.3, MIT). Причина: только async — общий цикл событий с backend на FastAPI, новые поля Bot API появляются быстрее. Альтернатива: python-telegram-bot 22.8 (Bot API 10.0, LGPL), если нужны встроенные `JobQueue` и `persistence`. Проверка поддержки: нужные методы (`AnswerWebAppQuery`, `SetChatMenuButton`, поле `web_app` у кнопки) есть в установленной aiogram 3.31.0 — импорт из `aiogram.methods` и `model_fields`, а не версия Bot API на сайте; итоговый JSON содержит нужные поля. Не поддерживается: проверка initData — отдельный код на backend.

## Проверка

Результат содержит выбор и причину, конкретную версию, минимальные зависимости, неподдерживаемые функции и проверенную альтернативу. При реализации подтвердите импорты, типы и итоговую сериализацию нового поля в чистом окружении.

## Типичные ошибки

- Выбор по звездам или популярности и миграция рабочего бота без функциональной причины.
- Вывод «функция поддерживается», потому что она есть на сайте Bot API, без проверки установленной версии.
- Пакет с похожим именем вместо SDK поставщика; обертка сообщества названа официальной.
- Синхронный SDK платежки вызван прямо из async-обработчика.
- В проекте две библиотеки Bot API или Telethon вместо Bot API для обычного бота.
- Миграция сведена к замене импортов: состояния пользователей и сессии теряются.
