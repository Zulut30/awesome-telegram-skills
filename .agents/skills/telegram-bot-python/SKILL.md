# Telegram-бот на Python

Прочитай зависимости, lockfile и существующий entrypoint. Сохраняй выбранную библиотеку, включая pyTelegramBotAPI. Для нового Python-проекта без предпочтений начни с aiogram и проверь текущую совместимую версию.

Для aiogram прочитай [references/aiogram.md](references/aiogram.md); для python-telegram-bot — [references/python-telegram-bot.md](references/python-telegram-bot.md); для TeleBot — [references/pytelegrambotapi.md](references/pytelegrambotapi.md). Эти ветки альтернативны.

## Реализация

Собери один работающий вертикальный сценарий: конфигурация → запуск → update → прикладная операция → ответ. Получай токен из конфигурации окружения; `.env.example` должен содержать только имена настроек и безопасные примеры.

Используй типы и механизмы установленной библиотеки. Оставь обработчикам разбор Telegram-события и представление ответа; вынеси правила и запросы к хранилищу в тестируемые операции. Выбирай масштаб структуры по задаче, без обязательного набора слоев.

В async-обработчиках используй неблокирующие клиенты. Ограничивай время внешних вызовов. Длительную работу помещай в управляемые задачи или очередь, если она нужна; не запускай бесконтрольные фоновые задачи на каждый update.

Закрывай HTTP-клиенты, подключения и хранилища при остановке. Для сохраняемого диалога выбери storage согласно нужной устойчивости; состояние в памяти не переживет рестарт. Согласуй ключ состояния с пользователем, чатом и темой.

## Проверка и передача

Запусти существующие проверки проекта и релевантный сценарий с синтетическим update. Проверь отсутствие текста в message, повторное нажатие кнопки и ошибку внешнего сервиса, когда это влияет на реализацию. Если тестовый токен доступен, проверь запуск и ответ через Telegram; иначе явно назови оставшуюся runtime-проверку.

Передай точную команду запуска из фактического окружения проекта и необходимые настройки. Сохрани совместимость версии Python, выбранного менеджера зависимостей и lockfile.
