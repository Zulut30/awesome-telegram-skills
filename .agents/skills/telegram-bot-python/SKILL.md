# Telegram-бот на Python

Прочитайте зависимости, lockfile и существующий entrypoint. Сохраняйте выбранную библиотеку, включая pyTelegramBotAPI. Для нового Python-проекта без предпочтений начните с aiogram и проверьте текущую совместимую версию.

Для aiogram прочитайте [references/aiogram.md](references/aiogram.md); для python-telegram-bot — [references/python-telegram-bot.md](references/python-telegram-bot.md); для TeleBot — [references/pytelegrambotapi.md](references/pytelegrambotapi.md). Эти ветки альтернативны.

## Реализация

Соберите один работающий вертикальный сценарий: конфигурация → запуск → update → прикладная операция → ответ. Получайте токен из конфигурации окружения; `.env.example` должен содержать только имена настроек и безопасные примеры.

Используйте типы и механизмы установленной библиотеки. Оставьте обработчикам разбор Telegram-события и представление ответа; вынесите правила и запросы к хранилищу в тестируемые операции. Выбирайте масштаб структуры по задаче, без обязательного набора слоев.

В async-обработчиках используйте неблокирующие клиенты. Ограничивайте время внешних вызовов. Длительную работу помещайте в управляемые задачи или очередь, если она нужна; не запускайте бесконтрольные фоновые задачи на каждый update.

Закрывайте HTTP-клиенты, подключения и хранилища при остановке. Для сохраняемого диалога выберите storage согласно нужной устойчивости; состояние в памяти не переживет рестарт. Согласуйте ключ состояния с пользователем, чатом и темой.

## Проверка и передача

Запустите существующие проверки проекта и релевантный сценарий с синтетическим update. Проверьте отсутствие текста в message, повторное нажатие кнопки и ошибку внешнего сервиса, когда это влияет на реализацию. Если тестовый токен доступен, проверьте запуск и ответ через Telegram; иначе явно назовите оставшуюся runtime-проверку.

Передайте точную команду запуска из фактического окружения проекта и необходимые настройки. Сохраните совместимость версии Python, выбранного менеджера зависимостей и lockfile.
