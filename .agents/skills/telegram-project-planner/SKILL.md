# Планирование Telegram-проекта

Превратите продуктовую идею в конкретный план реализации. Сначала учтите существующий код, выбранный стек, среду запуска и ограничения пользователя. Если информации мало, продвигайте независимую часть работы и уточняйте только решения, которые существенно меняют продукт.

## Выбрать форму продукта

- Для команд, уведомлений и коротких последовательных действий начните с бота.
- Для визуального каталога, календаря, корзины или сложной формы рассмотрите Mini App вместе с ботом.
- Определите, где используется продукт: личный чат, группа, канал, inline mode. Укажите пользователя, вход в сценарий и наблюдаемый результат.
- Отделите Bot API от пользовательского клиента MTProto. Не предполагайте возможности пользовательского аккаунта у обычного бота.

## Спроектировать минимальную систему

Основной стек этого набора — Python для ботов и backend, TypeScript для Mini Apps. Сохраняйте существующий стек; для нового бота без предпочтений предложите aiogram и проверьте текущую версию перед реализацией. Frontend-фреймворк и Python web-framework выбирайте по потребностям проекта. Не требуйте React, Redis, очереди или отдельные микросервисы без объяснения их пользы.

Опишите путь одного действия: пользователь → обработчик или frontend → прикладная операция → хранилище → ответ. Бизнес-правила должны работать независимо от Telegram-объектов. Для Mini App покажите границу между неподтвержденными данными браузера и серверной сессией. Отметьте операции, которые могут повториться, и способ не выполнить их дважды.

Для Mini App включите компактную и широкую компоновку, владельца формы/навигации, fallback (запасной вариант) для недоступных возможностей Telegram и критерии приемки на телефоне, планшете и ПК. Учитывайте узкое desktop-окно и tablet split view. Для детализации структуры может пригодиться telegram-mini-app-architecture; при его отсутствии опирайтесь на текущий код и официальную документацию, не делая соседний навык обязательным.

Для MVP достаточно перечислить сущности, роли, критические переходы, конфигурацию окружения и способ запуска. Обоснуйте polling или webhook применительно к выбранному хостингу. Для платежей сначала классифицируйте товар и проверьте действующие правила Telegram.

## Результат

Сохраните проектный документ там, где пользователь держит проектную документацию. Включите границы MVP, схему компонентов, принятые решения и этапы с критериями готовности. Различайте обязательные возможности и расширения. Для первого этапа укажите вертикальный сценарий, который можно действительно запустить и проверить.

[Возможности ботов](https://core.telegram.org/bots/features), [создание первого бота](https://core.telegram.org/bots/tutorial), [Mini Apps](https://core.telegram.org/bots/webapps). Перед обещанием конкретной возможности проверьте ее наличие и ограничения в текущей документации.
