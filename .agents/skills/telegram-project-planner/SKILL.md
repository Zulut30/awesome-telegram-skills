# Планирование Telegram-проекта

Преврати продуктовую идею в конкретный план реализации. Сначала учти существующий код, выбранный стек, среду запуска и ограничения пользователя. Если информации мало, продвигай независимую часть работы и уточняй только решения, которые существенно меняют продукт.

## Выбрать форму продукта

- Для команд, уведомлений и коротких последовательных действий начни с бота.
- Для визуального каталога, календаря, корзины или сложной формы рассмотри Mini App вместе с ботом.
- Определи, где используется продукт: личный чат, группа, канал, inline mode. Укажи пользователя, вход в сценарий и наблюдаемый результат.
- Отдели Bot API от пользовательского клиента MTProto. Не предполагай возможности пользовательского аккаунта у обычного бота.

## Спроектировать минимальную систему

Основной стек этого набора — Python для ботов и backend, TypeScript для Mini Apps. Сохраняй существующий стек; для нового бота без предпочтений предложи aiogram и проверь текущую версию перед реализацией. Frontend-фреймворк и Python web-framework выбирай по потребностям проекта. Не требуй React, Redis, очереди или отдельные микросервисы без объяснения их пользы.

Опиши путь одного действия: пользователь → обработчик или frontend → прикладная операция → хранилище → ответ. Бизнес-правила должны работать независимо от Telegram-объектов. Для Mini App покажи границу между неподтвержденными данными браузера и серверной сессией. Отметь операции, которые могут повториться, и способ не выполнить их дважды.

Для Mini App включи компактную и широкую компоновку, владельца формы/навигации, fallback Telegram capabilities и критерии приемки на телефоне, планшете и ПК. Учитывай узкое desktop-окно и tablet split view. Для детализации структуры может пригодиться telegram-mini-app-architecture; при его отсутствии опирайся на текущий код и официальную документацию, не делая соседний навык обязательным.

Для MVP достаточно перечислить сущности, роли, критические переходы, конфигурацию окружения и способ запуска. Обоснуй polling или webhook применительно к выбранному хостингу. Для платежей сначала классифицируй товар и проверь действующие правила Telegram.

## Результат

Сохрани проектный документ там, где пользователь держит проектную документацию. Включи границы MVP, схему компонентов, принятые решения и этапы с критериями готовности. Различай обязательные возможности и расширения. Для первого этапа укажи вертикальный сценарий, который можно действительно запустить и проверить.

## Источники

[Возможности ботов](https://core.telegram.org/bots/features), [создание первого бота](https://core.telegram.org/bots/tutorial), [Mini Apps](https://core.telegram.org/bots/webapps). Перед обещанием конкретной возможности проверь ее наличие и ограничения в текущей документации.
