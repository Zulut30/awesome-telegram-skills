# Операторские сценарии

## Матрица полномочий

Опиши capabilities по реальным действиям, например `orders.read`, `orders.cancel`, `payments.refund`, `users.support`, и scope tenant/магазина. Названия являются примером модели сервиса. Одной роли superadmin и проверкой `is_admin` в UI нельзя доказать изоляцию остальных операторов.

Backend query применяет scope до pagination/count/export. Поиск по ID не должен обходить этот фильтр. Сведения о существовании чужого заказа могут быть чувствительны; выбери согласованный ответ отказа/отсутствия.

Принцип «актуальные права» должен иметь операционное значение: серверная проверка, ограниченный кеш/permission version и сериализация опасной операции с отзывом. Для длинного bulk job перепроверяй право при dispatch по согласованной границе; уже отправленная внешняя операция не становится отмененной из-за revoke.

## Изменение объекта

Пример отмены заказа передает order ID, ожидаемую revision и scoped operation ID. Backend проверяет допустимый переход, права и текущую revision в транзакции. Повтор того же ID/payload возвращает прежний результат; новый payload с прежним ID отклоняется.

Существенная запись и audit event сохраняются согласованно: одна DB транзакция либо устойчивый outbox. Внешняя финансовая операция имеет промежуточный/unknown исход и путь сверки; общей транзакции БД и provider нет. Журнал не должен объявлять успех по нажатию кнопки.

Confirmation показывает объект/сумму/эффект и не является разрешением со стороны модели на внешнее действие вне пользовательского запроса. Read-only preview не выполняет операцию.

## Списки и bulk

Определи сортировку со стабильным tie-breaker, cursor/page и область фильтров. При refresh выбранный объект согласуется с новым серверным состоянием. Для больших списков используй server pagination, а virtualization добавляй по измеренной необходимости.

«Выбрать все» явно различает видимую страницу и всю выборку. При bulk запросе используй фиксированный набор либо документированный snapshot; не увеличивай выбор случайно новыми строками. Отчет содержит per-object success/denied/conflict/unknown без персональных payload.

CSV/export создается только для разрешенных полей и scope; учитывай spreadsheet formula injection по формату экспорта. Не публикуй выгрузку в общедоступном каталоге.
