# Platega.io

Определи товар, платежный маршрут, merchant, среду и доступные методы магазина. Применимость внешней оплаты в Telegram проверь до выбора checkout. Для протокола прочитай [references/platega.md](references/platega.md).

Выбери официальный SDK после проверки происхождения либо небольшой HTTPS adapter. Формируй заказ и цену на сервере. Сохраняй payment attempt до запроса и `transactionId` после него; выдавай пользователю только подтвержденную provider redirect-ссылку.

Метод оплаты выбирай по настройкам магазина, не по случайной цифре из примера. Уточни необходимость metadata, данные клиента и доступность рекуррентного сценария. Не копируй демонстрационные credentials из документации.

Проверяй callback headers, связывай provider ID с локальным заказом и сверяй сумму/валюту. Критический переход подтверждай актуальным статусом через API. Не допускай неизвестные статусы к выдаче и не считай frontend return URL доказательством оплаты.

После надежной записи callback быстро отвечай; выдачу и уведомление делай с транзакцией/outbox. Повтор либо нарушение порядка callback не должны повторять выдачу или отменять подтвержденный факт без соответствующего terminal event.

Для timeout создания платежа не выдумывай provider idempotency header: используй локальный attempt и сверку. Возврат и рекуррентное списание моделируй отдельными операциями. Промежуточный ответ на отмену не означает завершенный возврат.

Проверь создание ссылки, проверку статуса, неверный secret, duplicate callback, отмену и reconciliation в доступной тестовой среде провайдера. Если sandbox не подтвержден документацией или магазином, используй mocks и явно отметь отсутствие live-проверки.
