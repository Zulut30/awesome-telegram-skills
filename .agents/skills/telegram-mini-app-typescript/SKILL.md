# Mini App на TypeScript

Проверьте `package.json`, lock-файл, `tsconfig.json`, формат модулей и фреймворк интерфейса. Сохраняйте существующий SDK или нативный мост Telegram (bridge), если они подходят задаче. Для нового проекта берите минимальный шаблон на TypeScript; React не обязателен.

При подключении Telegram или смене SDK прочитайте [references/bridge.md](references/bridge.md). Не смешивайте методы разных SDK и нативного моста по похожим именам.

## Типы и границы

Опишите небольшой адаптер Telegram: данные запуска, проверка доступности возможностей, готовность и подписки на нужные события. Используйте типы установленного SDK. Если нужны собственные объявления типов, описывайте только проверенные поля; не скрывайте недоступность API через `any` или non-null assertion.

Держите обращения к Telegram API на границе приложения: прикладная логика не читает глобальный `window.Telegram` в каждом компоненте. В режиме превью в браузере адаптер может подставить явно включенную заглушку, но она не проходит как авторизация на рабочем сервере.

Для Python-сервера определите HTTP-контракты запросов и ответов. Если проект уже использует OpenAPI, переиспользуйте схему и установленный генератор; иначе хватит небольшого API-клиента. Типы TypeScript не проверяют JSON из сети во время выполнения: проверяйте недоверенные ответы на границе там, где это нужно.

## Конфигурация и жизненный цикл

Разделяйте публичные настройки интерфейса и серверные секреты. В Vite переменные `VITE_*` попадают в клиентскую сборку: токену бота и ключам доступа там не место. Проверяйте обязательный адрес API и режим запуска при старте.

Отменяйте запросы при закрытии экрана, отбрасывайте устаревшие ответы и не создавайте подписки повторно. При серверном рендеринге (SSR) не обращайтесь к объектам браузера на сервере. Изменение входа реализуйте вместе с серверной проверкой initData, а не с локальным `user_id`.

Отличайте загруженный мост от подтвержденного запуска и сессии: наличие `window.Telegram` само по себе не означает вход через Telegram. Настройте явные режимы — Telegram, превью для разработки и предусмотренное состояние вне Telegram. Параметр адреса `demo` не должен включать заглушку авторизации в рабочей сборке. Смена данных запуска или пользователя сбрасывает связанный кеш и старые запросы.

## Проверка

Запустите отдельную проверку типов и рабочую сборку командами проекта: сборщик не всегда проверяет типы. Убедитесь, что рабочая сборка использует нужный адрес API, не включает заглушку авторизации и не содержит серверной конфигурации. Затем проверьте один основной сценарий внутри Telegram; результаты превью в браузере укажите отдельно.
