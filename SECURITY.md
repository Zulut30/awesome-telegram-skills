# Политика безопасности

*English: report vulnerabilities privately via GitHub → Security → “Report a vulnerability”. Do not open public issues for security problems.*

## Поддерживаемые версии

Проект находится в экспериментальной стадии (0.x). Исправления безопасности выпускаются только для последней минорной версии.

| Версия | Исправления безопасности |
| --- | --- |
| 0.24.x и следующая выпускаемая минорная версия | да |
| Более ранние 0.x | нет: обновитесь до последней версии |

После выпуска 1.0 эта таблица будет заменена политикой поддержки из [docs/versioning.md](docs/versioning.md).

## Как сообщить об уязвимости

1. Откройте [приватное сообщение об уязвимости](https://github.com/Zulut30/awesome-telegram-skills/security/advisories/new) (GitHub → вкладка **Security** → **Report a vulnerability**).
2. Не создавайте публичный issue, pull request или обсуждение с деталями уязвимости.
3. Опишите затронутый компонент или скилл, версию, шаги воспроизведения на синтетических данных, ожидаемое и фактическое поведение и оценку последствий.

Не прикладывайте настоящие токены ботов, `initData`, сессии MTProto, платежные данные и персональные данные. Если без них воспроизвести нельзя, опишите, какие данные нужны, — мы согласуем безопасный способ передачи.

## Что входит в область

- Python-пакет `awesome-telegram-patterns` и TypeScript-пакет `@awesome-telegram/patterns`;
- примеры в `examples/` и скрипты в `scripts/`;
- инструкции скиллов в `.agents/skills/`, если они советуют небезопасное решение: например, доверие к `initDataUnsafe`, выдачу доступа до подтверждения оплаты, вывод токена в лог.

Уязвимости самого Telegram, Bot API, клиентов Telegram и сторонних SDK (aiogram, python-telegram-bot и других) сообщайте их владельцам, например через [программу Telegram](https://core.telegram.org/bug-bounty). Если такая уязвимость затрагивает рекомендации этого проекта, сообщите и нам.

## Сроки

| Этап | Цель |
| --- | --- |
| Подтверждение получения | до 3 рабочих дней |
| Первичная оценка серьезности | до 7 дней |
| Исправление критической и высокой серьезности | до 30 дней |
| Публикация advisory | после выпуска исправления, по согласованию с автором сообщения |

Мы указываем автора сообщения в advisory, если он не просит об анонимности.

## Добросовестное исследование

Проверяйте уязвимости только на собственных тестовых ботах, синтетических данных и локальных копиях проекта. Не атакуйте чужих ботов, Mini Apps, платежных провайдеров и инфраструктуру Telegram. Добросовестное исследование в этих рамках мы не считаем нарушением.

## Для владельца репозитория

Приватные сообщения работают, только если в **Settings → Code security → Private vulnerability reporting** включен параметр **Enable**. После включения отправьте тестовое сообщение со второго аккаунта и закройте его, чтобы убедиться, что канал доходит до мейнтейнеров.
